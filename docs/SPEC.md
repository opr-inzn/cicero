# Cicero — product spec for the clean rewrite

Cicero is a font manager for macOS 15 and later (SwiftUI, Liquid Glass on macOS 26, Apple silicon only; the network only for updates; see "macOS 15").
This is a ground-up rewrite: new code and architecture, same product. The user shaped every
behaviour below; keep them. Never mention or reference any other font manager app anywhere.

Writing rules for all UI text: macOS HIG — Title Case for menu items, buttons and window titles,
sentence case for descriptions; short plain words; typographic apostrophes (’) in every string. No
ellipses anywhere, against the HIG: not on items that ask for more input (Export Fonts, Back Up), nor in progress text ("Finding fonts"; counts after
a comma: "Copying fonts, 3 of 10"). The one "…" left marks a cut-off preview in the coverage set editor; the menu items macOS adds (Settings…,
Services, AutoFill, Start Dictation) keep theirs: SwiftUI puts the Settings item's title, and its visibility, back
whenever the menu updates.

No hover states: nothing changes under the pointer (tooltips and the column-resize cursor aside). AppKit's
toolbar buttons and segmented pickers light up on hover in a grey of their own, so the toolbars use Cicero's
(ToolbarPicker, the .toolbar button and toggle styles, at AppKit's sizes): one grey for a toggle that's on
and a button being pressed. A picker's chosen segment is a grey lens of interactive glass, 3 pt inside the
capsule on every side, that slides to the next one chosen.

## Windows

1. **Main window** — sidebar | browser (or a font page pushed over it) | optional Info panel.
2. **Settings** — tabs General, Folders, Sidebar, Coverage (the character sets; a short name keeps the tabs evenly spaced). General's sections: Appearance, Installation (where activated fonts' files go, added duplicates), Activation (asking before many, Open at login, Adobe documents' fonts), Library (what's listed, Adobe apps' test fonts included, guessed classifications), Maintenance, Updates.
3. **Character Toolbox** (⌥⌘T) — tabs Text and Languages.
4. **Compare** (⌥⌘C).
5. **Quick Look** (Space in the browser, ⌘Y) — a floating panel with the selected family.

## Sidebar

- Header "Library" with an **Edit**/**Done** button. Edit mode shows a checkbox on every row and every
  section header; unchecked items are dimmed, and disappear when you click Done. Sections and character set
  groups stay open or closed as outside it, and open and close the same way (one state for both). Switching
  isn't animated: hundreds of rows animating in and out ran into each other.
- Fixed rows: All Fonts (books.vertical), Active (checkmark.circle), Inactive (circle.dashed),
  System Fonts (apple.logo, only while system fonts are shown), Problems (exclamationmark.triangle, count badge).
- Sections, each collapsible and hideable:
  - **Folders** (+ adds folders). The folders Adobe apps load fonts from by themselves — /Library/Application Support/Adobe/Fonts, ~/Library/Application Support/Adobe/Fonts (all Adobe apps) and the Fonts folder next to any Adobe app, like /Applications/Adobe InDesign 2026/Fonts (that app only) — are one "Testing" item (`WatchedFolder.adobeAppsID`), shown while it has fonts (row menu: Reveal in Finder). Adobe Fonts (every CoreSync file, on for every app or only in Adobe apps) are one "Adobe Fonts" item (`adobeFontsID`), shown while it has fonts, whatever the switch (row menu: Manage in Creative Cloud; no Export Fonts); a family is in it when any copy is, like a folder. Type designers export fonts there to test them; they're unrelated to Adobe Fonts from Creative Cloud (CoreSync), which are always listed and tagged "Adobe Fonts", never "Adobe". They aren't in the user's folders: Settings → General → Library → "Show test fonts installed for Adobe apps" (on by default; saved as `showAdobeAppFolders`, formerly `showAdobeFonts`) switches them, and only them; adding one of them with + turns the switch on. Every folder row's menu starts with Rename Folder (a prompt with the current name; the name lives in `UserData.folderNames` by folder ID, the folder on disk keeps its own; empty or the folder's own name removes it; shown wherever a folder's name is: sidebar and window title, Settings → Folders, smart set rules, Problems, Use Copy From; Cicero's own items take one too; forgotten when the folder is removed). Row menu for the user's folders: Reveal in Finder; "Fonts in This Folder" picker —
    "Inactive" / "Active" / "Active in Adobe apps" / "Active in Specific App" (asks for its name); Remove Folder from Library.
    Cicero's own Deactivated folder appears here when it has fonts, and so do its "Font Library" (row menu: Rename,
    Reveal in Finder; see Activation) and "Added Fonts" (doc), the
    files added one at a time (see Opening and adding files; row menu: Reveal in Finder, which selects them).
  - **Sets** (+ menu: New Set, New Smart Set, New Application Set). Sets (square.stack), application sets (app.badge.checkmark) and smart sets (gearshape). A set's menu has Activate with Apps (Edit Apps once it has some).
    Menus start with Activate Set, Activate Temporarily and Deactivate Set
    (Activate Smart Set, Deactivate Smart Set), for every family the row shows; then Rename Set, Delete Set;
    Edit Smart Set, Delete Smart Set.
  - **Tags** (`SidebarSection.tags`; a family has any number, the license tags to begin with, on no family; called
    License in 1.5 to 1.5.2, when a family had one at a time; + new tag: the New Tag sheet, a name and a
    row of colour dots, None, the Finder's seven and sand, starting on the first colour no tag has; an empty name
    is the colour's; a name that's taken says so and can't be created). A new library starts with Licensed (green),
    Licensed + Non-Commercial (sand), Unlicensed (red), Partially Licensed (yellow), Public Domain (purple), Open
    Source (blue) and Trial (orange). One row per tag in the order they were made, a dot in its colour (a picture,
    not a tinted symbol, which the list darkened on the accent colour; or tag when it has none). Menu:
    Rename Tag (a name that's taken says so), Color (None, Red, Orange, Yellow, Green, Blue, Purple, Gray,
    Sand; each with its dot, as are tags in a family's Tag menu: `.titleAndIcon`, since menus built
    with the macOS 27 SDK hide images otherwise), Delete Tag (off every family, and out of smart set rules).
  - **Foundries**. Menu: Rename Foundry
  - **Classifications** (+ new classification). Serif, Sans Serif, Monospaced, Script, Ornamental, Symbol — only the ones
    with families — then the user's own (always shown, in the order they were made), then Unclassified. A family's
    classification is the one its fonts suggest unless the user put it in another: the family menu's Classification
    submenu (Automatic (Sans Serif), every classification, New Classification; a classification is checked when the
    user put every family in it, so choosing the one Automatic suggests keeps the family there), the Info panel's Classification row
    (Change menu, the same items), or dropping families on a classification row. Menu: Rename Classification (built-in
    ones too; their own name back undoes it; a name that's taken says so; overrides, smart set rules and the sidebar
    follow), Delete Classification for the user's own (its families go back to Automatic, its smart set rules go).
  - **Coverage** (titled like the Settings tab; + new custom set). Collapsible groups — Latin S–XL, Adobe Latin, Google Fonts, Unicode Blocks, Your Coverage Sets — with every set shown unless hidden (Edit, Settings). The section starts collapsed, as Foundries does (Classifications starts open), and within it Unicode Blocks and Google Fonts. Menu for custom: Edit Coverage Set, Delete Coverage Set.
- The menus of sets, smart sets, tags, folders, foundries, classifications and character sets also have Export Fonts and Export Font List (that row's families, see Export and backup). Every row menu also has Hide from Sidebar and Edit Sidebar, and so does a character set group's title, where Hide from Sidebar hides every set in the group (`hideGroup`), and with them the group.
- Order: rows drag to a new place within their own section (character sets within their group), never
  into another one; as in Finder's sidebar, the rows around the place they'd land slide apart to open a gap
  for them. Character set groups move by dragging a group's title onto another's, which is highlighted: the
  dragged group takes its place (a click on the title opens or closes the group, so the title can't also
  drag in the list). Sections don't move: a click on a title opens or closes it, and a drag does nothing (an
  order saved when sections could be dragged is kept; Reset Order puts them back). Items that are gone for now (System Fonts while
  system fonts are off, an empty Deactivated folder) keep their place; new items go last.
- Several rows of one section (or character set group) can be selected with ⌘- and ⇧-click and dragged
  together: they land side by side in the gap, in their order. The browser then shows the fonts in any of them. Selecting in another section starts over there.
- Moving through the sidebar quickly (holding an arrow key, clicking from row to row) moves the selection at
  every step; the browser shows the last one once the selection rests for a moment.
- Dropping family names (drag from the browser or the Character Toolbox; dragging one of several selected families drags them
  all, as their menu acts on all of them) onto a set, tag, foundry or classification adds them; the
  row they're over is drawn in the accent colour with white title and symbol (a status's dot keeps its colour).
  Drags are AppKit's (`FontDragSource`, started from a drag gesture): what's dragged is a small label at the pointer,
  "Aa" in the family's regular style and its name, with a red count when it's several, or a style row's name in that
  style. Drops land on AppKit views behind the rows and the Compare window (`FontDropTarget`), which leave clicks to
  the rows, so the label goes the moment it's dropped, as in the Finder. With SwiftUI's draggable the dragged item had
  the whole card's frame, and on macOS 26 the label slid to that frame's corner after a drop; SwiftUI's drop
  destination also held it up a third of a second longer.
- The list draws no selection (`selectionHighlightStyle = .none`): a selected row has its title and symbol in the accent
  colour on a light grey rounded fill, whether or not the list has focus (`SidebarHighlight`).
- Creating a set, tag, classification or coverage set un-hides its section.
- Settings → Sidebar lists the same items, in the sidebar's order, as Finder-style checkboxes, with
  Reset Order and Show All.

## Browser

- Title = selected item's name (several: "Serif and Script"); subtitle "1.298 families · 716 active" (or "… · checking characters, 400 of 1.298" while coverage is computed and the list depends on it).
- Toolbar, left to right, each in a glass capsule of its own, 8 pt apart like the Info button and the search field
  (ToolbarCapsule: AppKit merges neighbouring items into one capsule, and ToolbarSpacer(.fixed) leaves 16 pt): view switcher
  [List list.bullet | Grid square.grid.2x2 | Specimens rectangle.grid.1x2] · [Preview Options textformat.size] · [Info info.circle] · native search field.
- **List** (rows under column headers in a lazy stack, like the grid: not a SwiftUI Table, which makes every
  row's cells whenever an accessibility client — a password manager's autofill, say — walks the window, and
  with a thousand families kept the app busy for minutes each time it came to the front): Status (switch) ·
  Name (+ tag dot, status tag) · Preview (sample in the font, 17 pt) · Styles · Classification · Foundry · Year
  (hidden; the earliest year among the family's faces: each face's earliest 1950-or-later year in its copyright notice, else
  its head table's created year from 1985 on; read when scanning and kept in the face cache) · Rating (hidden; the
  family's stars, ★ to ★★★★★, empty for none; sorts by stars) · Latin S–XL
  (largest of Latin S/M/L/XL the family fully has) · Adobe Latin (shown as "AL 3") · GF Latin, GF Cyrillic,
  GF Greek (hidden; largest of each script's Google sets, shown as "Plus"; GF Latin African branches off
  Core, so it isn't in the series) · any set no series covers: a Unicode block, GF Latin African, a custom
  set (hidden; ✓ when the family has all of it, "12 missing" when some) · Date Added (hidden) · Format
  (hidden). The headers are a bar under the toolbar (`safeAreaBar`, with the hard scroll edge effect), so
  the rows go under both together. Click a header to sort by it, again to reverse; right-click the headers to
  show or hide columns, the character set columns (series, then built-in single sets, then the user's own after a separator) under Coverage (Status,
  Name and Preview always show); drag the gap between two headers to resize the column on the side away from
  the preview, which makes up the difference, so the edge follows the pointer (shown columns and widths saved).
  When the room runs short (the Info panel open), the preview gives way first, then the other columns down to
  their minimums. The preview isn't clipped to its row: tall glyphs run over the row's edges rather than lose
  their descenders. Selection as in the other views.
- **Grid**: tiles — status tag + switch on top, big centered sample ("Aa Gg 123", or the sample
  text when set), name with its tag dot, and what the family's styles span, in Title Case: "9 Weights · 3
  Widths", "8 Weights · 16 Styles"; at the bottom right, the kinds of file it comes in ("OTF",
  "Variable", "OTF · Variable": extensions in capitals, variable fonts just "Variable"). No axis
  ranges: a variable font's styles are its named instances, placed by their axis values; a static
  font's by its names and classes. Weights count the words in style names (Bold, Bd, U Lt) first — many static files leave
  every class at 400 and variable fonts nudge instances off round values — then the axis value or
  OS/2 class. Widths: a variable instance's wdth value, with instances whose names write the same
  width words (Condensed, not XXX Condensed) counted once; a static font's OS/2 width class unless
  it's normal, then the name. A family with more styles than weight and width tell apart (italics,
  optical sizes, other axes, small caps cut as fonts of their own) adds "N Styles". The full caption is
  the tooltip. Tiles scale with the preview size.
- **Specimens**: cards like the grid's tiles (light grey, tinted and outlined when selected, 12 pt apart, 16 pt from the edges) — name, tag dot, status tag, "Foundry · N styles", switch; the sample at preview size, lined up as Preview Options' alignment says; up to 14 style names set in themselves (+N more).
- Tag dot: an 8 pt circle in the tag's colour, with no ring (side by side, 2 pt apart, for a family tagged
  several ways before 1.5). Cards are opaque (the card's grey on the window's background), so the
  picture dragged to the sidebar looks like the card.
- Selection: click, ⌘-click, ⇧-click, ⌘A, arrow keys (↑/↓ in the list and specimens; in the grid ←/→ a tile and ↑/↓ a row; ⇧ extends), Esc clears (closing Quick Look first when it's open), and so does a click between families or below the last, typing a letter jumps, Return or double-click opens the font page, Space opens Quick Look; rows are draggable as family names. Right-click → family menu.
- Search (`SearchQuery`) matches where a word begins (at the start, or after a character that's neither a letter nor a digit) in a family's name (its own, or the one it shows in the Mac's language), foundry (as the user renamed it too) or note, or a style's name, PostScript name, designer or vendor ID, so "am" finds American Typewriter but not every family from a foundry with "am" inside its name; when nothing in the listed families matches that way, runs may be inside words of names (not foundries, designers or PostScript names), so "vetica" finds Helvetica. Or it matches what kind of family it is, by terms that begin with what's typed: variable, monospaced/mono, italics/italic, the classification it's shown in (a built-in one also by its usual words: sans serif/sans-serif/sans, script/handwriting/cursive, ornamental/decorative/display, symbol/dingbats), display or text (a name's size word, as similar fonts read it, or an opsz axis), condensed/compressed/narrow and extended/expanded/wide (a style off the regular's place on a wdth axis, else off OS/2 width class 5), slab serif/slab (OS/2 family class 5), optical size/opsz, its tags, its file extensions, and for a monospaced family what its family class says. The query's words split into runs that each match something, so "variable sans" finds variable sans serifs. A run that's exactly one of those words (a keyword) is looked for only in the family's and styles' names and the note, not the foundry, designers or PostScript names, so "mono" doesn't list Monotype's fonts.
- Search suggestions (`searchSuggestions`): up to eight of the families the browser would list (sidebar selection, or Show Similar Fonts) whose shown names begin with the whole query, then those with a later word that does, each group alphabetical; section "Families", each row "Aa" in the family's regular style (28 pt wide, so names line up) and its name. Choosing one completes the field with the name; a search that's exactly a listed family's name selects that family and brings it into view (`jumpTargets`).
- Empty states per selection (no folders or added fonts → Add Folder, Add Fonts; nothing active; empty set; smart set with no matches → Edit Smart Set; character set still being checked; search with no results).
- A small glass capsule bottom-right while a scan takes longer than 0.4 s ("Finding fonts", "Identifying fonts 200 of 4000"); quicker scans show nothing.
- Selecting Problems shows the Problems view instead of a list.
- Status tags (small capsules, the capitals and a symbol's drawing centred in them, measured): System; Partly active (orange); "Adobe Fonts" (purple) when every face is from Adobe Fonts (`Family.isAdobeFonts`), whatever its state, tooltip "From Adobe Fonts, managed in Creative Cloud" (plus "Active in Adobe apps only." for those); "Testing" (red) for app-only in Adobe apps (Adobe's folders, where type designers test fonts), else the app's name, e.g. "InDesign", tooltip saying the app loads it from a folder by itself; "Temporary" (blue, with Activate Temporarily's clock) for temporarily active; "App Set" (graphite, with New Application Set's app.badge.checkmark) for on for an application set.
- Switches: a small switch drawn in SwiftUI (not a native NSSwitch per row — too slow), with tooltip
  ("Installed with macOS" / Activate / Deactivate) and VoiceOver toggle semantics. Families whose
  every face is in (or was moved out of) one app's own folder, like Adobe's, have three positions: on in
  that app only (knob halfway, track lightly tinted), on everywhere, off everywhere. Clicking goes
  app only → everywhere → off → app only; tooltips "On in Adobe apps only. Click to turn on in every
  app." / "On in every app. Click to turn off, Adobe apps included." / "Off. Click to turn on in Adobe
  apps only." The styles table's switches do the same per style.

## Font page (pushed over the browser; Esc or Back returns)

One scrolling page, top to bottom: header, text, styles, similar families, glyphs with the ligatures after the characters (no tabs).

- Toolbar: Info · the search field, as in the browser (typing in it goes back to the browser with the matches). No Preview
  Options: the page has its own size and alignment, and takes preview text (styles list), weight and spacing from the browser's.
- Header: family name in its own regular face (34 pt), with room above and below for glyphs reaching past the font's ascent and descent, so a script font's swashes don't run into the line under it; then "Foundry · OpenType PostScript · Variable · 2 Styles · 1 active · 1 inactive" (no classification; how many styles are active, partly active — on in one app only — and inactive, leaving out the kinds with none: "2 partly active", "3 active · 2 partly active · 1 inactive"), and on the right Activate (prominent) / Deactivate, worded as in the family's right-click menu (Activate in All Apps and
  Deactivate in Adobe Apps for a family in an app's folder, Activate Permanently, Activate Remaining Styles); locked families get a disabled Deactivate with the reason as tooltip, except that a family with any face from Adobe Fonts gets "Manage in Creative Cloud" instead, which opens the Creative Cloud app (com.adobe.acc.AdobeCreativeCloud; it takes no links to its Fonts page) or, without it, https://fonts.adobe.com/.
- **Text**: Style picker (Automatic = follows preview weight; or a specific style), Size slider 12–240 pt, alignment left/center/right (its own, centered at first; a left alignment chosen when there were two stays), a big editable text (default "Sphinx of black quartz, judge my vow.") that grows with what's typed, remembered. Lines are the Preview Options line spacing apart (an exact line height, so tighter than the font's own works too). Every glyph draws whole, however far past its line it reaches: the editor keeps room above the lines for as much of the font's height as the line spacing leaves out (each baseline sits the font's descent above the bottom of its line) and below them for glyphs lower than the descent, reaches out over the page's margins for glyphs past the lines' ends, and its lines draw outside themselves (TextEditor cut them off at the font's ascent and descent). Esc goes back, as elsewhere on the page.
- **Styles** (only when the family has more than one style): laid out like a table — Preview, Style, Weight, Status (the style's switch and its state, e.g. "Active until Cicero quits"); right-click → style menu, which ends with the family's Add to Set, Tag, Rating and Classification under the family's name.
- **Similar** (when the family's letters are measured and others are too): a title like the styles' (subheadline, semibold, secondary), 50 pt below the styles: Similar, and at the end Show All (text like the sidebar's Edit: subheadline, secondary, `StillButtonStyle`; not a bezeled button), which lists the 12 that Show Similar Fonts does, right there, and becomes Show Less; then the six nearest families (see Similar fonts), one row each between dividers; the choice stays from one page to the next. Rows 44 pt high whatever the font's line spacing: the family's name, whatever the preview text, set in it at 20 pt and the preview weight; a click opens its page, at its top as from the browser (a page of its own for each family, never the last one's scrolled), right-click its family menu with Not Similar to <the page's family>. While the pointer is over a row, Not Similar (small) at its end, in the room the name leaves, marks it (see Similar fonts); for VoiceOver, an action of the row. While the library's letters are first measured: the Similar title, a divider and "Comparing this family’s letters with the others’"; for a family without measurements, nothing.
- Right-click on the header or the text → the family menu, as in the browser. The text, an NSTextView, shows it after Cut, Copy and Paste (an NSHostingMenu made at each right-click; macOS adds AutoFill).
- **Glyphs**: the style the Text is set in (`previewStyle`: the Style picker's, else the one nearest the preview weight), at its weight and moved axes; while another style's are read, the last one's stay, drawn in that style, rather than a spinner. Heading 56 pt below the styles with "404 characters" (and "· 12 ligatures", "· 40 alternates" when the style has any) and a filter field (character, Unicode name or U+ code; ligatures whose characters hold the text, or with that code, too), then one section per group with counts (`GlyphGroup`: Uppercase, Lowercase, Uppercase Accents, …, in the order a type designer lists them), each group's characters in code point order, with no order of its own, headers pinned while scrolling, cells set in the font (a mark that combines with the character before it, like those in Combining Diacritical Marks, drawn from its outline: set alone it has nothing to sit on and showed nothing); click a cell for a popover with the character large, its name, and a grid: Unicode (U+00E9), HTML (the HTML 4.01 named entity when there is one, but &lang; and &rang;, which HTML5 gave ⟨ and ⟩, then the numeric reference &#xE9;); each value selectable. A feature glyph's popover shows its character's codes and the feature. **Copy Character** puts the character on the clipboard as plain text (a feature glyph's character, which its tooltip says looks like the glyph with the feature on). Right-click a cell for Copy Character, Copy Unicode and Copy HTML Entity (named, else numeric).
- **Ligatures** (only when the style has any), after the blocks, in the Glyphs section. A character whose glyph a ligature is too (ﬁ, usually also U+FB01 in Alphabetic Presentation Forms) is listed once, as the ligature, whose popover says "Also U+FB01, Latin Small Ligature Fi"; the header's character count still counts it, and the filter finds it by that character or code. A pinned header per feature like a block's —
  Standard (liga), Discretionary (dlig), Historical (hlig), Contextual (clig), Required (rlig) Ligatures, with
  counts — and rows of cells like the characters' (52 pt, as many to a row): the ligature glyph drawn from its outline by
  glyph ID at the characters' 26 pt (a ligature has no character to set; centred on the ascender and descender, or the
  glyph where it reaches past them, scaled down when wide or tall), its characters in the tooltip; click
  for a popover with it large, "f + f + i", the U+ codes, the feature and Copy Characters ("ffi"); its right-click
  menu has Copy Characters and Copy Unicode ("U+0066 U+0066 U+0069"). Read from the GSUB table: ligature
  lookups (type 4), through extensions (7), and the lookups contextual ones (5, 6) apply. Components map to
  characters through the cmap (the lowest code point when several share a glyph), a component that is itself a
  ligature to its characters; ligatures of other glyphs (alternates, positional forms no character maps to) are
  left out. AAT-only fonts (morx) list none. Up to 3,000 per feature.

## Quick Look (Space in the browser; Fonts → Quick Look ⌘Y)

- A floating panel with the family selected in the list, grid or specimens. Space or ⌘Y opens it and closes it again; Esc closes it before it clears the selection. It opens only with families selected and never over a font page, and closes when nothing is selected any more, when a font page opens (↩ opens the family the panel shows, double-click and ⌘↓ as usual) and when the main window closes. The menu item reads "Close Quick Look" while it's open. Space never jumps to a family by its letter.
- The panel never takes the keyboard (an NSPanel that can't become key: non-activating, floating, hidden while Cicero isn't the active app). The main window stays key, so ↑/↓ (and ←/→ in the grid) go on moving the browser's selection and the panel follows at once. It opens centred over the main window at the size it was last resized to (520 × 440 at first), with a full title bar (not a utility window's small buttons and title), and steps aside while the main window shows a sheet or alert, so the activation prompt its switch can bring up isn't hidden.
- Content: the family name as the window title (the title bar in the page's colour); a large sample in the regular style — the Preview Options preview text (56 pt, wrapping), or when that's empty "Aa Gg 123" (96 pt, shrinking to fit) over A–Z, a–z and 0–9 (24 pt) — with the family's chosen OpenType features, the preview letter and line spacing and alignment; below it, when the family has more than one style, every style's name set in itself (a variable font's named instances at their own weight), scrolling with the sample; and a glass bar at the bottom: "Foundry · OpenType PostScript · Variable · 12 styles · Active" (the styles' status when they share one, else "3 of 12 activated") and the family's switch.
- Several families selected: one at a time, in the browser's order, with ‹ › and "2 of 5" in the bar (on past the last back to the first). ←/→ in the list and specimens go through them and leave the selection as it is; in the grid, where ←/→ move the selection, the panel follows that. A family just added to the selection (a click, ⇧↓) is the one shown; several added at once (⌘A, ⇧-click) keep the one shown.
- Never holds up the selection: a font file nothing has read yet is read off the main thread while room is kept for its text, and only the styles on screen are made, so big variable families with many named instances step as fast as any.

## Info panel (a pane floating at the trailing edge like the sidebar and in its colour, 300 pt wide, with 20 pt corners on macOS 26 and corners concentric with the window's on macOS 27, starts 16 pt below the toolbar, level with the first row of the grid and of specimens, and as far from the grid's last column as tiles are from each other (12 pt), stays put when a font page opens, toggled by ⓘ (a toolbar toggle, highlighted while the panel is open) / ⌘I; an overlay on the split view, since the detail column's stack swaps the whole column for a pushed page, and each page makes room for it)

- Family name; segmented Info | Features, in the tabs picker style on macOS 27 (no style picker: it describes the style being previewed).
- Info: Note (a plain text field, "Add a Note", growing to 12 lines; Return starts a new line, as Option-Return does; saved a second after typing stops, when it loses focus and when the panel goes to another family, so lists by notes don't change with every key; only spaces and new lines take the note away), Status, Tags (the family's, each with its dot, or No Tags, and a Change menu: the Tags menu), Rating (five stars, star.fill up to the family's rating; clicking one gives that many, clicking the one it has takes the rating away; one adjustable element for VoiceOver), Family (the fonts' own name, also when the family shows by one in the Mac's language), Style, Full name, PostScript name, Version, Designer, Manufacturer, Vendor ID (OS/2 achVendID, padding trimmed; left out when blank or not printable), Weight, Variable weight, Glyphs, Format, Embedding (Installable, Editable, Preview & Print or Restricted, from the OS/2 fsType), Copyright, Languages ("213 languages, including English, German, …" + Show All popover grouped by script with search; full support marked), Coverage (largest set per series the face has, e.g. "Latin S, Adobe Latin 3, GF Latin Core", plus "Latin M needs 12 more characters"), Location + Reveal in Finder, Other copies.

## Similar fonts

- Show Similar Fonts (family menu, Fonts menu): the browser shows the family and the 12 nearest of the listed families (`SimilarFonts.longestList`), the closest first, in any view, like a search: no sidebar item selected, title "Similar to Inter", the search field cleared and then filtering them, the family selected and brought to the top. A bar over the list (a safe-area bar, under the toolbar): sparkle.magnifyingglass, "The families that look most like Inter, the closest first.", Done (plain text in the accent colour; back to the sidebar items selected before, the family selected there when it's listed, and to the font page that was open, if any). Choosing a sidebar item ends it too. The list keeps the order, with no column's sort arrow, until a column's title is clicked.
- Measured (`LetterMeasurements`): each family's regular style, a variable one at weight 400 and at its own optical size (the one its variation sets, else the axis's default: CoreText's automatic optical sizing is off, as it would size the font to the 1,000 units it's measured at and take an axis's default for none set, making every one its largest, display cut), from the outlines of H, I, O, a, c, d, e, g, l, n, o, p, x at 1,000 units to the em, against the H's height: x-height, ascender (l, d), descender (p, q), weight (the H's and n's stems), contrast (the o's top and bottom against its sides, the H's crossbar against its stems), stress (the o's thickness going round as a wave, its tilt from upright times how much it changes), width (the lowercase's average advance against the x-height), capital width, the o's width against its height, spacing (the room either side of n, o, H, O), slant (the font's angle, else the I's and l's lean), serifs (how far the feet of H and n reach past the stems and how thick they are, past a cupped foot's hollow; the I's and l's when neither can say), aperture (the share of directions out of c and e that meet no ink), squareness (how much of its box the o fills), the a's and g's stories (crossings going up through the middle), monospacing. Too few measures (fewer than 10 of 18) and the face isn't measured: most fonts of other scripts, symbol fonts, bitmap emoji.
- Embedded (`LetterEmbedding`): the same style, at the same optical size, its H O R A a e g n o s t y f k 2 5 drawn from their outlines (`LetterImages`), white on black, each centred in a 64-pixel square on a baseline 18 pixels up, at a size that makes the x-height 20 pixels (the capitals 40 at most), with each letter's advance at that size, in squares (what the squares, centred by the ink, don't show, as how a monospaced face's letters are all as wide), given to a Core ML model (Resources/LetterEmbedding.mlpackage, about 3 MB, compiled into the app by build-app.sh) that answers 128 numbers of length 1, close together for faces that look alike. The model learned from about 1,200 Google Fonts families (OFL, Apache and UFL only, the tenth of them it was judged on left out; scripts/embedding), each family's uprights at each width and optical size and its italics a design of their own, batched with its siblings named for another size, width or kind (DM Serif Display and Text, Roboto Mono and Roboto): designs as close as their Google tags of kind (Didone, geometric, formal script, stencil…) are alike, an upright and an italic less so, and two weights of a design closest, each design told from the others as well, so that slant and width count; Google's tags, category and the letter measurements, the widths most, told from them. Fewer than 8 of the 16 letters and the face isn't embedded.
- Compared (`SimilarFonts`): each measure in fixed steps of about a visible difference (not the library's spread, which for contrast is mostly the gap between sans serif and serif faces, and for slant next to nothing), capped at 4 steps, weighted (width 6, capital width and round width 3, as the embedding hardly tells widths; weight and serif length 2.5; contrast, monospacing 2; x-height, slant 1.5; stress, serif thickness, aperture, the a's story 1; squareness, the g's story 0.75; ascender, descender, spacing 0.5), a measure only one has counting 1.5 steps, one neither has none; the embeddings' distance in steps of 0.1, weighted 1.5. Families of different classifications (as the sidebar has them, guesses and the user's own included) are 1 further apart, added to the distance: a few places down a list, where the sixth nearest and the twelfth are often less than one apart, not out of it. Of families whose names say a size (`SimilarFonts.OpticalSize`: Text, Caption, Micro, Agate; Display, Headline, Poster, Deck, Banner, Titling, Fine), those of the family's own come first among them, in their order, then the others, its sibling for the other size among them, when its name says one too; families whose names don't say keep their places. Copies of one design, as their names say (`SimilarFonts.design(of:)`: the name without a leading Test and without Trial, Unlicensed, Test, Demo, Beta, Variable, VAR, VF, Pro, Std, Plus, ProN, StdN, SC, TC, HK, MO, a weight (Semi Bold as one), a version or a date (v0.2, 2.001, 260417) at its end, also before an Italic or Oblique there), are listed once, the nearest of them, and the family's own not at all. Done over the 12 nearest designs whatever the limit, so a font page's six are the start of Show Similar Fonts' 12, and a sibling among the 12 stays in it. Families hidden from lists are left out.
- Not Similar (a font page's Similar rows, the family menu in Show Similar Fonts' list): the user says families listed among another's similar fonts don't look like it (`AppModel.markNotSimilar`). They're kept in the user data (`UserData.notSimilar`: family → the families marked, the latest last; empty lists are dropped as it loads; kept when a family goes to the Trash, as its copies still count; in backups), and leave the family's list at once, the next taking each one's place, as `SimilarFonts` skips them; it leaves theirs, and every copy of either (`design(of:)`) is left out the same way. Marked ones leave the selection. Toast "Futura marked not similar to Inter" ("3 families marked…") with Undo, for 6 seconds (`AppModel.undoTime`), which takes back only those. While usage statistics are shared, each mark is also reported (`SimilarReports`, see Data and privacy) once Undo has passed, so a mark undone is never sent (without them it stays in the user data only); the report holds the list as it was before the mark.
- `MeasurementIndex` measures and embeds every family's regular style after coverage, on all cores at utility priority (about a second for a thousand families on an M-series Mac, and a third of one more for the embeddings, the model on the Neural Engine one family at a time), and keeps the results in Caches/letters.plist by file stamp; Rebuild Font List clears it. Raise its version when measuring or the model changes.

## Library and fonts

- Sources: everything CoreText reports active (`CTFontManagerCopyAvailableFontURLs`), macOS's own /System/Library/Fonts (CoreText's lists leave out some of its fonts, like Times, Courier, Iowan Old Style, Seravek and many Noto fonts, though apps can use them; its files count as active, from macOS, and its hidden "." families are left out as anywhere), ~/Library/Fonts and /Library/Fonts, watched folders, the files added one at a time (Added Fonts; skipped while missing or dataless), Cicero's Deactivated folder (~/Library/Application Support/Cicero/Deactivated). A file in the Fonts folders is active when CoreText lists it, or, for the few it leaves out (fonts with hidden names), when `CTFontManagerGetScopeForURL` says so; otherwise it's not activated (it's turned off in macOS, or macOS hasn't noticed it yet). Without a list from CoreText at all, files in the Fonts folders count as active. Files Cicero registered itself (in place, or for a while) that the list leaves out are asked about the same way: the list hides some fonts though they're on, like copies of the macOS fonts it hides. Files in watched folders that iCloud or another file provider has taken off the Mac (dataless) are skipped until they're downloaded: reading one would download it.
- Files: otf ttf ttc otc dfont (not web fonts, woff woff2, anywhere: not in folders, added files or CoreText's active list); each face read with CoreText (PostScript name, family, style, full name, OS/2 weight class (fallback from traits), OS/2 width class, italic, monospace, OS/2 family class, PANOSE (kind and serif style as a classification), letter shapes (below; only for faces with no family class and no monospace flag), manufacturer, version, designer (name ID 9), OS/2 vendor ID, wght axis range, visible variation axes (tag, name — the tag when the font gives none — and the named instance's value on each), embedding (the OS/2 fsType's usage bits; the least restrictive when several are set, as before OS/2 version 3), and the GSUB feature list's tags, kept as the `OpenTypeFeature`s smart sets ask for (ss01–ss20 as Stylistic Sets, cv01–cv99 as Character Variants, cswh as Swashes)). Unreadable files are kept for Problems. Parsed faces are cached by path + modification date + size; Date Added (Finder's, fallback creation date) is cached with them.
- Families group faces by family name (hidden "."-prefixed families skipped). A family shows, and sorts, by its name in the Mac's language when its fonts have one (`LocalizedNames`): the name table's typographic family names (name ID 16, else ID 1) in every language but English are kept with each face in the caches, keyed by the full language ("ja-Jpan-JP"), Windows' and Unicode's records before the Mac's (in the script's encoding), so changing the Mac's language needs no reading again. The first of `Locale.preferredLanguages` the font has a name in wins, the region's own first, the same script only; English first means the fonts' own names. The family's id, which the user's data keys by, is always its own name; the Name rule and search match either, toasts use the one shown, and dragging a family carries its own. The same PostScript name in several files is one face: the active file wins, the others are "other copies"; Date Added is the earliest.
- Face state: active (from macOS / installed for all users / inside an app / Adobe Fonts (CoreSync) / your Fonts folder / used in place by Cicero / temporarily until Cicero quits / for an application set / another app), inactive, or "active in <App> apps" for watched folders marked app-only and the Testing folders. Also "Active in Adobe apps", as for Adobe's folders, for the Adobe Fonts Adobe apps turned on for themselves (as for a document), which Creative Cloud keeps under hidden names in ~/Library/Application Support/Adobe/CoreSync/plugins/livetype/.w (`Locations.adobeFontsInAdobeApps`, scanned always, hidden files included, and watched): app "Adobe", no folder item, and locked like every CoreSync file (`LibraryFace.isAdobeFonts`: no activate, temporary activation or deactivate; the switch sits halfway, disabled; the engine refuses them too). Such a copy ranks after every other, so a copy of the user's stays the face to switch, and it never makes a user's file spare (`SpareCopies`).
- Family state: all active (system if all from macOS) / partly / inactive / app-only / system.
- Classification, the first that says something: monospace (any face), OS/2 family class of the lightest upright face that isn't a style of ornaments (class 12, or Ornaments or Dingbats in its style name, as Hoefler Text's), unless the family has nothing else (1,2,3,4,5,7 serif, slab serifs included; 8 sans; 9 ornamental; 10 script; 12 symbol; sub-classes don't change it), name hints (mono/code, stencil/inline/outline/fraktur/blackletter as ornamental, sans/grotesk/gothic, serif/slab/garamond/antiqua, script/brush/hand, symbol/dingbat/emoji), letter shapes, then PANOSE (kind 2 with serif style 2–10 serif, 11–13 sans, flared and rounded nothing; 3 script; 4 ornamental; 5 symbol; the proportion digit is ignored, as it often says monospaced wrongly). Letter shapes and PANOSE count when the upright faces (all faces, in a family of italics) that have one agree; letter shapes make a family monospaced only when every one of those faces is, and otherwise its monospaced faces don't count. Where both say something and differ, the letters are right, so they come first.
- Letter shapes (`LetterShapes`): monospaced when a drawn i, m and W (I, M and W without lowercase) are exactly as wide; letters not drawn yet, all as wide in unfinished fonts, and fonts in three widths (i and m alike, W wider) don't count. Else the capital I and lowercase l, flattened, measured with exact scanlines (non-zero winding). Each must be one stem: one run of ink at 30, 50 and 70 % of the glyph's height, widths within 1.3×, on a straight line leaning as the font's italic angle says, at most two contours. Serif when the ink 1–5 % from the bottom (and, for the I, from the top) reaches more than 0.3 stem widths past the stem on both sides of the I and at the foot of the l; sans when the I's ends reach less than 0.12 and the l's foot doesn't reach both ways (a tail to one side is fine). A font with only one of the two (capitals or lowercase only) goes by that one; an l alone is sans only with no tail either. Anything else (Verdana's serifed I with a plain l, scripts, italic l's tails) gives nothing: a wrong classification is worse than none.
- Guessing: while Settings → General → "Classify fonts automatically" is on (`classification.guessesFromNames`), the families still Unclassified get Apple Intelligence's guess from the name (macOS 26 only), else the model's from the letters (below). At the first launch (no user-data.json or library.json and no saved setting) an alert asks "Classify Your Fonts Automatically?" (Not Now, and Classify as the default button, side by side) as the window opens, and nothing is guessed until it's answered (`classification.asksAboutGuessing`, asked again at the next launch until then); a library from before keeps guessing as it did. Without guessing, what the fonts say still classifies them, as do the user's choices and classifications imported from FontExplorer X.
- Letter guesses (`AppModel.letterGuesses`): `LetterEmbedding`'s model also answers how likely its letters are serif, sans serif, script or ornamental (a small classifier on the embedding, fitted to Google Fonts' families: handwriting and script tags script; display families with a decorative theme ornamental; then Google's stroke, category or tags, slab serifs as serif; monospaced ones left to their advances). `MeasurementIndex` caches the likelihoods with the embedding; a family gets the classification when it's at least 0.7 likely (`letterGuessLikelihood`; held-out Google families: right 95 % of the time, saying something for 89 %), refreshed as measurements arrive. Not for a family whose letters say serif for some styles and sans for others. The Info panel then says "Guessed from the shapes of its letters".
- Name guesses (`ClassificationGuesser`, app; macOS 26, as macOS 15 has no model apps can ask): while guessing is on and `SystemLanguageModel.default` is available, the families still Unclassified are asked about one at a time in the background (not ones whose upright faces' letters say serif for some and sans for others, `Family.mixesSerifAndSans`: the model picks one of the two for them), in a new `LanguageModelSession` each, with greedy sampling and guided generation into serif / sansSerif / monospaced / script / ornamental / symbol / unknown. The prompt is the family name, foundry, designer and up to 12 style names. Answers, unknown among them, are kept in Caches/Cicero/classification-guesses.json (with the prompt's version), so each family is asked once; rate limits and missing model assets stop until the next scan, other failures until the next launch. A guess applies only while the family is Unclassified and has no classification the user chose, before the letters' guess (the model answers only when a name says); the Info panel then says "Guessed from the name by Apple Intelligence". Turning the setting off forgets the guesses. On-device only: never `PrivateCloudComputeLanguageModel`.
- Foundry: manufacturer name trimmed of Inc./LLC/GmbH/…, URLs and copyright lines dropped, casing unified; user can rename a foundry or set a family's foundry (drop onto foundry).
- At launch the window opens with the library the last scan built (saved in the caches after every scan that changes it; faces turned on until Cicero quit, or for an application set in an earlier login session, show as off), and the launch's scan, started before the window is made, replaces it.
- Rescan: on launch, right after activation changes, on CoreText's registered-fonts-changed notification (posted to the app's own notification center, for any app's changes; debounced; while an operation runs they wait for the scan it starts when it finishes, or one right after it when it starts none), when font files come or go in the scanned folders (FSEvents), and when the app becomes active after ≥60 s. An unchanged scan must cost almost nothing (fingerprint; no UI churn).
- Show system fonts (Settings → General) off hides system families everywhere, and the System Fonts item with them.

  /Font n`, the default style sheet's for a run that names none), never AdobeInvisFont; no pixels read, smart
  objects not opened. Each font once. A file it can't read says "Couldn’t read the fonts in “Name”."
- Settings → General → "Activate the fonts documents use in Adobe apps" (`activatesDocumentFonts`, off at first, as
  macOS then asks for Automation once per app): while InDesign, Illustrator or Photoshop is frontmost,
  `DocumentFontWatcher` asks it every 0.5 s (none while the screens sleep) for its open documents' fonts or files,
  sending the `core/getd` Apple Events itself, off the main thread, to the app's process (10 s timeout): no
  AppleScript to compile (~25 ms a time, and compiling or running a script opens an app that has quit), a few ms a
  check, and no measurable CPU in the app. InDesign: `fPSN`, `fFam` and `fSty` of every `FonT` of every `docu`
  (codes from InDesign itself, which has no sdef; a missing value counts as "", so the lists line up). Illustrator
  `aiFS`, Photoshop `Dpth` of every `docu`, read with `DocumentFonts`, again only once saved since; Photoshop fails
  them all for an unsaved one, so then each document is asked in turn, and Illustrator's "/Untitled-1" is skipped.
  None of them asks macOS (CTFontManager font requests) for a document's font. The library's styles that are off,
  or on for apps, go to `AppSetWatcher.request`, which keeps them on for that app (`whileAppsRun`, the App Set tag)
  until it quits; turned off by the user meanwhile, they stay off until then. Cicero opening again takes up the

  the styles none of that app's sets has), so the fonts of a background app's documents don't go off. An app that
  refuses (-1743) isn't asked again until Cicero opens again. InDesign and Illustrator answer while their Missing
  Fonts dialog is open and set the text once it's closed; Photoshop shows none and takes the fonts up within
  seconds. Measured 2026-10-20: InDesign in front takes up a registered font on its own after 1.5–10+ s, and within
  0.5 s of coming to the front; the `.idlk` lock file appears ~15 ms into an open, too late to beat its font check;
  a file in ~/Library/Application Support/Adobe/Fonts isn't taken up faster. Photoshop's `app.refreshFonts()` takes
  the font up at once but freezes it for ~2 s, so it isn't used.
- Sheet "Fonts in “Brochure.indd”", "12 fonts · 8 on · 2 off · 2 missing", one row per font, missing first, then off,
  then on, each by name: a status symbol (green check, dashed circle, orange triangle), the name (family and style,

- Matching: the library's face with the PostScript name, else the family and style names (case, spaces, hyphens

## Activation

- Install method (Settings → General → Installation): Ask each time / Copy into ~/Library/Fonts / Move into ~/Library/Fonts / Leave the files where they are. "Ask" shows a sheet: Install a Copy, Move Into Fonts Folder (files added one at a time), Leave Files Where They Are, an Activate Temporarily button (until Cicero quits; hidden when the fonts are already on until then), "Remember this choice (you can change it in Settings → General)".

Before the install method's sheet. Application sets, imports and restores never ask.
- Every switch moves the moment it's clicked and stays there while the operation runs; the scan after it confirms or corrects it. A switch that's moving ignores clicks.
- Copy: copied into Cicero's staging folder (~/Library/Application Support/Cicero/Staging) and moved into ~/Library/Fonts, so macOS never sees a half-written file (unique name if needed; a file of the same name with the same contents counts as already there), then registered (persistent) so apps get it at once — macOS takes seconds to notice a new file by itself. Remembered as installed copy → origin. A copy macOS won't turn on is taken out again and the font counts as failed.
- Font Library (`UserData.fontLibraryPath`, ~/Cicero/Font Library at first — `Locations.defaultFontLibrary`, in the home `userFonts` is in, so a test run with another home keeps its own — filled in at launch when empty, backed up with the settings). "Keep installed fonts in Cicero’s Font Library" (Settings → General, under the install method; off by default, `installsIntoFontLibrary`): Copy and Move (the setting, the Ask sheet's Install a Copy and Move Into Font Library, opened files) put the file into `<library>/<family>/` through the staging folder (a file of the same name with the same contents counts as already there; unique name otherwise), register it persistently where it is and record it both as an installed copy (→ origin) and in place; nothing goes into ~/Library/Fonts. The family is the one the face was turned on for; for an opened file, its first font's, read from the file. The folder's name is the family's with "/" and ":" as "-", without control characters, leading dots (hidden) or surrounding spaces, at most 200 bytes, and an extension that would make it a package (".app", ".bundle") without its dot; the file's name when nothing is left. A file from the Deactivated folder that goes into the library is removed from there once its copy is on (it only kept the font while it was off), unless it's the origin of another installed copy. Faces whose file is in the library are always registered in place, whatever the install method, never copied; turning one off only unregisters it (the file stays, listed and off; never the Trash or the Deactivated folder). Move to Trash removes library files like any, and a family folder left empty but for .DS_Store goes (also after a copy macOS wouldn't turn on); the library folder itself stays. The library is a scanned folder (`UserData.scannedFolders`, ID `fontLibraryID`) whether the setting is on or off: watched, listed only when it's there (a library that isn't there yet isn't missing; one on a disk that isn't connected, or that Cicero may not read, counts as away like a watched folder), shown under Folders as "Font Library" while it has fonts (renamable, no activation picker or Remove, a Folder rule option), described as "in Font Library" in the duplicates sheet. Library copies of watched folders' fonts are installed copies, so Use Copy From places them with their originals, and Problems never counts the library's files as duplicate spares. With the setting on, while Cicero has installed copies right in ~/Library/Fonts (records' keys, never the user's files), a row says "Cicero installed Inter and Roboto before, in ~/Library/Fonts." with Move Them: as one queued operation the ones on are unregistered, each moves into its family's folder (unique name) and its record follows, then they're registered there and recorded in place; one that can't move stays and is registered again. Toast "Inter and Roboto moved into your Font Library". Turning the setting off moves nothing back. Change (next to the library's path) opens a folder panel (New Folder allowed) and refuses, in an alert saying why (`ActivationEngine.refusal`): a file, a Fonts folder (~/Library/Fonts, /Library/Fonts, macOS's) or a folder in one, Cicero's Application Support or Caches folder, macOS's or an app's folders, the library itself or a folder in it, a folder in a scanned folder, iCloud Drive (~/Library/Mobile Documents, or anything iCloud keeps, as Desktop & Documents) and other cloud services (~/Library/CloudStorage), a folder with anything but .DS_Store in it, and one Cicero can't write to. Otherwise, as one queued operation, the library's fonts registered persistently or for the session are unregistered, the empty folder chosen is removed and the library folder moved into its place (a rename on the same disk), the records' paths follow (installed copies, in place, temporary), the fonts are registered again there, and ~/Cicero goes once empty when the library was in its first place; if the move fails the library stays and its fonts go on again where they were. Toast "Font Library moved to ~/Fonts/Library". Restore: the backup's library (moved to this home) is a place fonts may go back to and records may name (installed copies and in-place registrations, which are turned on again like other in-place ones); restoring the settings brings the backup's library path (or keeps this Mac's for a backup from before there was one), restoring only fonts puts the backup's library fonts into this Mac's library, records moved with them.
- In place: CoreText persistent registration, remembered.
- A font only counts as activated once macOS reports its file active (`CTFontManagerGetScopeForURL`). Registration waits for fontd, so when the toast says "Inter activated" the font is in every app's font list. A font in a Fonts folder that macOS has off is turned on where it is.
- Fonts from app-only folders (Adobe) are always used in place — never copied. Turning one off
  everywhere moves its file into Cicero's Deactivated folder (the app would load it otherwise) and
  records where it was (`appFolderOrigins`); it stays listed with that folder. Activating it, or Use in
  Adobe Apps Only, moves it back first (beside a newer file of the same name; fails if the folder is
  gone). Folders the user can't write to (InDesign's, owned by root) can't be turned off this way.
- Temporary: CoreText session registration in place (app-folder fonts too: on in every app for that long, then back to where they were), always until Cicero quits (the only choice): unregistered on quit, leftovers from a crash unregistered at launch. Records saved with the former "until you log out" choice load as until Cicero quits.
- Deactivate: a copy Cicero installed goes to the Trash only when its recorded origin is still there with the same contents (size and bytes, a separate file: not the same one through a link, and not one iCloud has taken off the Mac). The whole file decides, so a collection or variable font goes only when every face in it is in the origin. Every other file in ~/Library/Fonts moves to Cicero's Deactivated folder: the user's own files, whatever other copies exist (macOS's, Adobe Fonts', an app's, another version), and installed copies whose origin is gone or changed. Nothing asks first: the Deactivated folder keeps every file, and turning the font on again puts it back. A file holds every face in it, so deactivating one style of a collection moves the whole file. Files in ~/Library/Fonts are unregistered before they move, so apps drop them at once; one that can't move is registered again. In-place/temporary → unregister (persistent, falling back to session). macOS, all-users, app and Adobe Fonts faces can't be turned off ("These fonts are managed by macOS or another app.").
- Activating permanently a temporarily active font ends the session registration first.
- Application sets: a set with apps (bundle ID, name, path). While one of its apps is open, its fonts that are off are registered for the session and confirmed active, like temporary activation (record scope `whileAppsRun`, with the bundle IDs of the open apps that want each file); when no open app wants a file any more it's unregistered. Fonts on for any other reason are never touched. `AppSetWatcher` follows `NSWorkspace.runningApplications` (it changes as an app starts launching, before it reads its fonts) and syncs when apps, sets, records or the library change; a font the user turns off, or on for good, while its app is open is left alone until the app quits. Registrations outlive Cicero quitting (the app may still be open) and are synced at the next launch; they end at logout anyway, so their records keep the login session (audit session ID + boot time) and ones from an earlier session are forgotten at launch. Works only while Cicero is open: Settings → General has Open at login (SMAppService), and the apps sheet offers it too.
- Move to Trash (family or style): unregister (in-place files and files in ~/Library/Fonts; registered again if they can't be moved), trash every file including other copies; never touches /System, /Library/Application Support/Apple, /usr, /private, app bundles, Adobe CoreSync; collections that also contain other families are named in the alert; removes the family from sets, its tag and foundry overrides. Alert "Move “X” to the Trash?" with destructive Move to Trash.
- Short toasts at the bottom, for 3 seconds (6 with Undo, `AppModel.showToast(_:undo:)`: a semibold Undo in the accent colour after the text, which does it and closes the toast), without a full stop, naming what they did (`FontNames`): a style by its name ("Inter Bold activated"), one family's styles by the family's ("Inter installed"), two families by both ("Inter and Roboto deactivated"), more by how many ("12 families activated until Cicero quits"); failures count files ("Couldn’t activate 2 of 5 files"), or name what failed when nothing worked ("Couldn’t activate Inter"). Wording throughout: "family" for what a row of the list is, "style" for one font in it, "fonts" as the loose general word and never an exact count, "font files" for files. "Moved to the Trash" follows the alert that named what goes.

## Export and backup

- **Export Fonts** (File, ⇧⌘E; "Export" in the family menu; "Export Fonts" in the sidebar menu of a set, smart set, folder, foundry, classification or character set) copies the font files of the selected families — with none selected, of every family in the list; from a sidebar row, that row's families — into a folder or a ZIP archive, for sending them to someone or a printer. The save panel's name defaults to the row's name, the family's name for one family, or "N Families"; a Format picker in it chooses Folder or ZIP Archive. The folder holds one subfolder per family with its files; one family's files go straight into the folder. Each file is copied once (a collection shared by several faces, or families, once), only each face's own file, not its other copies. Files that come with macOS or an app, and Adobe Fonts, are left out and the toast says so: "Exported 12 families. Left out 3 font files that come with macOS or an app" (one or two by name: "Exported Inter and Roboto"). Files are copied with FileManager (APFS clones) off the main thread; a ZIP is staged in a temporary folder and made with `ditto -c -k --keepParent`. The export is built in a private folder on the destination's disk and takes its place only once complete, so a failed or cancelled one leaves nothing behind; an item the save panel confirmed replacing goes to the Trash then, never written over. An item that is, or holds, a font file in the library (an exported one, any other, or one Cicero's records name), ~/Library/Fonts, /Library/Fonts, Cicero's folder or its Deactivated folder, or a watched folder is never replaced (by its path or where links lead): nothing moves and the toast says "“Fonts” holds fonts Cicero uses, so it wasn’t replaced. Choose another name or place." The result is revealed in Finder.
- **Export Font List** (File; the sidebar menu of a set, smart set, tag, folder, foundry, classification or character set) saves the selected families — with none selected, every family in the list; from a sidebar row, that row's — as a CSV file for a spreadsheet (`FontListCSV`): a header, then a row per family in the list's name order with Family (as shown), Styles (the count), Style Names, Foundry (the user's name for it), Designer, Version (each distinct one, without "Version " and build notes), Year, Format (the tiles' OTF / TTF / Variable), Classification, Status (Active, Active Temporarily, Partly Active, Inactive, Active in Adobe apps, Installed with macOS), Tags, Rating (1–5 or empty), Note and Files (one path per line). Several values in a cell are joined with ", "; cells with a comma, a quote or a line break are quoted, quotes doubled; one starting with =, +, -, @, a tab or a return gets an apostrophe first, so a spreadsheet takes it as text, not a formula. UTF-8 with a byte order mark, CR LF line ends. The save panel's name defaults like Export Fonts', with ".csv"; the file is revealed in Finder and the toast says "12 families listed in “Acme.csv”".
- **Back Up Library** (File; Settings → General → Backup) writes a `.cicerobackup` archive (a ZIP made with ditto), named "Cicero Backup 2026-10-13.cicerobackup" by default. A sheet first says what it holds — sets, smart sets, tags, character sets, folders and added fonts, foundry names, the sidebar, and the settings for activation, system fonts and fonts installed for Adobe apps — with a checkbox "Include font files" and their count and size ("3,812 files, 2.4 GB": every file in the library, other copies included, protected ones left out, sized off the main thread), then shows progress (a bar while copying, indeterminate while zipping) with Cancel, and reveals the file. Like an export, it's zipped in a private folder on the destination's disk and replaces an older file (through the Trash) only once complete, so Cancel or a failure leaves the older file and nothing else; it never replaces an item holding fonts Cicero uses. Inside: `manifest.json` (format 1, created date, app version, the home folder, `includesFonts`, and every font with its path — the home folder written as "~" — its place in the archive (`Fonts/<n>/<file>`, so names never clash), size, and how it was active: in ~/Library/Fonts, in place, an installed copy with its origin, or not active), `user-data.json` exactly as the store writes it, and the files.
- **Restore Library** (File; Settings → General) opens a `.cicerobackup`, unzips it to a temporary folder and asks "Restore the Backup from 13 October 2026?" with two checkboxes: "Sets, folders and settings" (what's inside: "4 sets, 2 smart sets, 7 tags, 3 folders, 12 added fonts and 1 character set"; replaces the current setup, which is saved first to ~/Library/Application Support/Cicero/Backups/Before Restore <date>.json — the sheet says so) and "Font files" (only when the backup has them: "Puts each file back where it was, unless one is already there."). "~" means this account's home folder, so a backup moves between Macs and user names; the paths in the user data move with it (folders and added fonts). Nothing is ever written over: a file already at a path is left alone. A backup is a file anyone could have made, so nothing in it is trusted: only font files go back (the extensions the scanner reads); a file's place in the archive must stay inside the unzipped folder (no "..", no absolute path, no symbolic link), else it's left out; and a file goes back only to a plain absolute path (no "." or "..", after "~" is expanded) inside a font location: ~/Library/Fonts, /Library/Fonts, Cicero's Deactivated folder, the watched folders and the Font Library in the backup's own user data (this Mac's library when only fonts are restored), Adobe's shared font folders and the Fonts folder next to an Adobe app. Missing folders are made; a file meant for anywhere else, or that can't go back (no permission, or a folder next to an app that isn't installed, like /Applications/Adobe InDesign 2025/Fonts) goes into ~/Fonts Restored from Cicero/ keeping its path under it (without "." or ".." parts), and that folder is added to the watched folders. Records describe this Mac and follow the same rule (installed copies only in ~/Library/Fonts or the Font Library, app-folder origins only for files in the Deactivated folder): the backup's installed copies count when both files exist and the copy is the backup's (this restore put it back, or it has the origin's contents; a different file this Mac already had there is no copy), its temporary activations are dropped, its app-folder origins count when this restore put the file back (activating would otherwise move a file this Mac already had into an app's folder), its in-place registrations are activated again (in place, through the activation engine) once a scan has found the faces, and the current records stay where their files exist. Then a rescan and a toast: "Restored 4 sets and 3,790 font files; 22 were already there." The file work runs off the main thread with progress and Cancel in the sheet; the records change is one queued operation, like an activation.

## Importing from FontExplorer X and Font Book

- **File → Import from FontExplorer X** reads FontExplorer X Pro's library on this Mac (~/Library/Application Support/Linotype/FontExplorer X/FontExplorer X.fexdb, with ~/Library/Preferences/com.linotype.FontExplorerX.plist for its Font Library's place, `fontFolderLocation`); without one, an open panel takes a `.fexdb`, a `.fexconfig` (a folder: FontDatabase.db and the plist) or a `.fexbackup` (a ZIP of those and the Font Library's files, unzipped with ditto into a temporary folder). Those dropped on the window or opened from the Finder open the same sheet; one library at a time, and none while an import runs ("Wait for the import to finish first"). The database is SQLite, copied first and opened read-only and immutable (`FontExplorerImport`, `SQLiteFile`): `containers` (a row per file: path, isSystemFont/isInSystemFolder, isSkyFont/isTypekit/isMLSFont, activate, count, lastActivated in seconds since 2001, comment, license fields), `fonts` (a row per face: psName, familyName, style, rating 0–5, labelColorID 1–7 for red, orange, yellow, green, blue, purple, gray), `sourceItems` (type 7 set, 8 folder, 6 smart set with specialFlag 1 for all and 0 for any, 31 application set whose type-32 child has the Autoactivate fonts and type-33 child the Autodeactivate ones; nested by parentSerialID; smart sets 1 and 3–6 are FontExplorer X's own and left out), `setContainers` (files, not faces), `smartGroupRules` and `applicationSetPaths` (.app paths). Paths in another home folder (the setting's, else the one most paths are in) are taken as in this one; a backup's Font Library goes to its place in this home folder (or where it was, when that's on this Mac), else ~/FontExplorer X/Font Library. A database's Font Library that isn't on this Mac (copied without it, or on a disk that isn't connected) is named in the sheet's note, with how many files were in it: "3 font files in ~/FontExplorer X/Font Library (not on this Mac)", then "2 other font files that aren’t on this Mac".
- **File → Import from Font Book** reads ~/Library/FontCollections/*.collection (not com.apple.*, but com.apple.Favorites as Favorites), or `.collection` files the user picks (`FontBookImport`): keyed archives of NSFontCollectionDictionary, whose NSFontCollectionFontDescriptors are read without AppKit (NSFontDescriptor decoded as its attributes): a family name alone is the whole family, a PostScript name (or a family and face) a style, a negative descriptor a style left out. A collection with any other attribute or a predicate picks fonts by rules and stays behind, named in the sheet. Named after the file, as Font Book shows it. Fixed Width, Fun, Modern, PDF, Traditional and Web are Font Book's own and start unchecked.
- **The sheet** (`ImportSheet`): "Import from FontExplorer X" and where from ("FontExplorer X’s library on this Mac" or the file) with Choose Another; checkboxes, each with a line under it: Fonts (the Font Library, "~/FontExplorer X/Font Library, 4,050 font files, listed where they are, without turning them on" or "… from the backup, put in …"; Fonts in other folders), Sets / Collections, Application Sets ("For Adobe InDesign 2024 · 3 styles"), Smart Sets ("3 rules, all of them"; one with a rule Cicero can't take is unchecked and dimmed: "Cicero has no rule for Format and Family Name ends with."), Tags, Ratings and Activations (Labels as tags, Ratings, Comments as notes, Activation history, Turn on the fonts that were on, checked when there are any), each list with Select All / Select None; then "Not imported: license details of 3 fonts and the fonts an application set turns off (Autodeactivate)." Import, Cancel. Then progress (putting a backup's fonts in place, with Cancel; reading the fonts) and what came over: "4 sets, 1 application set, 2 smart sets and 3 tags.", font files listed, styles turned on, families rated, families with notes from their comments, fonts not in the library, smart sets left out, apps not on this Mac; Done.
- **Importing** (`AppModel.performImport`, `LibraryImport`) saves the setup first as Backups/Before Import <date>.json; copies a backup's fonts (font files only, from inside the unzipped backup, never through a symbolic link; a file already there stays); then in one queued operation adds the Font Library as a watched folder named after the app (`folderNames`), and the other files to the added files (neither when a scanned folder has them already); scans; and matches each font to the library (`FontMatcher`, shared with Fonts in Document): by its file (a set takes every face in the file), else its PostScript name, else family and style names, ignoring case, spaces, hyphens and underscores. A set has a family whole when every face of it is in, else those styles; its name is "Folder / Sub / Set"; a set with a name that's taken gets the fonts and apps it doesn't have. Apps are found where they were, else by name in /Applications, /System/Applications and ~/Applications and the folders in them, else the newest with the same name but another year ("Adobe InDesign 2024" → "Adobe InDesign 2026"). Labels become tags called after their colours ("Red" … "Gray", like a tag made with a colour and no name), in those colours, given to each family any style of which has the label. Smart sets come over only with every rule: Family Name (is, begins with, contains, doesn't contain), Name (begins with), Manufacturer → Foundry (is, is not, contains), Designer (is, contains, doesn't contain), Is Activated → Status is (not) Active, Rating and Number of Activations → Rating and Times Activated (is, is more than), Contained In → Set (the imported one; left out when it isn't), Label → Tag, Last Activated and Import Date in the last 7 or 30 days → Last Activated and Date Added; one with the name of a smart set that's there stays as it is. A family's rating is its best style's, unless it has one; its note the comments on its files and styles, each once, one per line, unless it has one; its activations the most any of its files had and the latest date, Cicero's own if higher. The fonts that were on (activate = 1, not the system's or cloud fonts) are turned on in place. Only ever adds, so importing again changes nothing.

## Applications folder

- Open at login points at the copy that's running, and Sparkle replaces that copy, so both need Cicero in /Applications or ~/Applications (or a folder inside them), not on a disk image, in Downloads or at an App Translocation path. At launch, a copy elsewhere asks "Move Cicero to the Applications folder?" ("Application sets, opening at login and updates work only when Cicero is in the Applications folder."): Move to Applications Folder / Do Not Move, with a "Don’t ask again" checkbox. A binary run from .build (`swift run`) never asks.
- Turning on Open at login (Settings → General, or the apps sheet's Open at Login) outside an Applications folder shows the same alert without the checkbox instead of adding a login item; the moved copy then turns Open at login on.
- Moving copies Cicero.app into /Applications, or ~/Applications when the user can't write there; a Cicero.app already there goes to the Trash first (a Cicero running from it is asked to quit). The copy loses the quarantine attribute. The original goes to the Trash when it's on a writable volume, found through `SecTranslocateCreateOriginalPathForURL` when the app was translocated; a disk image it ran from is detached once Cicero has quit. A small shell script waits for Cicero to quit and opens the moved copy. A failure says "Couldn’t move Cicero to the Applications folder." with the reason.

## macOS 15

Cicero runs on macOS 15 and later (`.macOS(.v15)`, `LSMinimumSystemVersion` 15.0). What it uses of macOS 26 has a stand-in there (`Components/Compatibility.swift`), so on macOS 15 Cicero looks as that macOS's own apps do; macOS 26 is unchanged.
- Glass: the toast, the scanning capsule and Quick Look's bar are on the bar material with a hairline edge and a shadow (`glass(in:)`). The toolbar has the system's own controls, not Cicero's capsules: a segmented picker for the view and the Compare and Toolbox pickers (`ToolbarPicker`), the system's toolbar buttons (`toolbarButtonStyle()`) and toggles (`ToolbarToggleStyle`).
- Bars over a scroll view (the list's column headers, Show Similar Fonts' bar): an inset on the bar material that what scrolls goes under (`topBar`), without a scroll edge effect; the Toolbox's fading bars an inset too.
- Exact line heights (Quick Look's samples over several lines): the font's own line spacing plus what the setting adds; lines set tighter than the font's own spacing keep it (`lineHeight(_:natural:)`). The font page's sample (`SampleEditor`) is exact on both.
- Drag and drop (`drops(of:)`): `dropDestination(for:action:isTargeted:)`, which can't tell drags from Cicero's own windows (family drags are names, not files, so they don't outline the window anyway). Character set groups drag with `onDrag` (with `draggable` the title never started a drag there) and drop through a `DropDelegate` that proposes a move, forbidden onto the dragged group's own title.
- Sidebar sections are `collapsible(false)`, or the list adds a chevron of its own after a header's + (`notCollapsible()`).
- No Apple Intelligence model for apps: classifications are recognized from the letters only, and the first-launch alert, Settings → General and the Classify fonts automatically tag's tooltip say so (`ClassificationGuesser.readsNames`).

## Data and privacy

- Everything local: ~/Library/Application Support/Cicero (user data, Deactivated folder), ~/Library/Caches/Cicero (face, library and coverage caches, classification guesses). Nothing about the user or their fonts is uploaded, but for not-similar reports (below); Apple Intelligence's guesses are made by the model on the Mac.
- Not-similar reports (`SimilarReports`, `SimilarReport`): when the user marks families not similar (see Similar fonts) and Undo has passed, while Settings → General → "Share usage statistics" is on (`usageStatistics.isOn`, as for the launch signal; there's no switch of its own), Cicero POSTs one JSON report to `https://cicero.maximilianinzinger.com/api/similar-reports` over an ephemeral URLSession: `format` 1; `app`, `build`, `macOS` ("26.1.0"); `model` (`MeasurementIndex.version`); `mac`, the SHA-256 of a random UUID kept in the defaults (`similarReports.id`); `test`, true for a build signed without a team; `shownIn` (`page` or `browser`); `family`, the family the list is for; `notSimilar`, the names marked; `list`, the list as the user saw it before the mark, the 12 nearest (`SimilarFonts.longestList`) whatever the page showed. Each family: `name` (its own, `Family.id`), `style` (the measured regular's PostScript name), `foundry` (as the user named it), `classification` (as the sidebar has it; none for Unclassified), `measurements` (`LetterMeasurements` by measure name, those it has), `embedding` (the 128 numbers), `distance` (from the family; none for it). No font files, nor pictures of letters. A failed send isn't retried. At most 20 reports a day from one Mac (`SimilarReports.dailyLimit`, counted by the Mac's own day in `similarReports.day` and `.count` as each is sent; a report of several families counts once), so no one Mac uses up the 2,000 the store may take a month on Vercel's Hobby plan (one advanced operation each; over it, the store is out of use for 30 days); marks past it stay on the Mac. Turning usage statistics off removes this ID and the count too, and a mark then stays on the Mac. Nothing is sent from a binary run from .build. The website's function (private repo) checks a report's shape and keeps it, with the time it arrived and without the IP address, as one file in a private Vercel Blob store in Frankfurt; a script there downloads them for the training kit.
- Usage statistics (`UsageStatistics`): when the app has finished launching, while Settings → General → "Share usage statistics" is on (it is from the start, without asking; `usageStatistics.isOn`), Cicero POSTs one TelemetryDeck signal to `https://nom.telemetrydeck.com/v2/` over an ephemeral URLSession: type `TelemetryDeck.Session.started`, a new session UUID, `clientUser` the SHA-256 of a random UUID kept in the defaults (`usageStatistics.id`), and the payload `TelemetryDeck.AppInfo.version` and `.buildNumber`, `TelemetryDeck.Device.platform` ("macOS"), `.systemVersion` ("macOS 26.1.0") and `.systemMajorVersion` ("macOS 26"). `isTestMode` is true for a build signed without a team, like build-app.sh's ad-hoc one. Until TelemetryDeck has answered with a 2xx while `usageStatistics.countedAsNew` was unset, the same request also carries a `TelemetryDeck.Acquisition.newInstallDetected` signal (the same user and session, the same payload plus `TelemetryDeck.Acquisition.firstSessionDate`, the local day like "2026-10-14"), which TelemetryDeck's Acquisition charts count as a new user; then the flag is set, and kept when the setting is turned off, so a Mac counts as new once. A failed send isn't retried, except that signal at the next launch. Turning the setting off removes the ID, so turning it on again makes a new one. Nothing is sent from a binary run from .build, or while `UsageStatistics.appID` is empty.
- Updates (Sparkle 2): each time Cicero opens and once a day while it stays open, while Settings → General → "Check for updates automatically" is on (it is from the start, without asking), Cicero downloads the appcast from the latest GitHub release (`SUFeedURL`); Check for Updates does it at once. Sparkle's system profile stays off, so the request carries nothing but its user agent, "Cicero/1.0 Sparkle/2.10.0". An update the user accepts is downloaded from GitHub and installed only if its EdDSA signature matches `SUPublicEDKey`. The appcast holds the latest version only, with its CHANGELOG.md section as Markdown release notes.
- The rewrite reads the existing user data file (library.json, read by `UserDataStore`) once and keeps working from its own file; the old file is never modified.
