# Cicero — product spec for the clean rewrite

Cicero is a font manager for macOS 15 and later (SwiftUI, Liquid Glass on macOS 26, Apple silicon only; the network only for updates; see "macOS 15").
This is a ground-up rewrite: new code and architecture, same product. The user shaped every
behaviour below; keep them. Never mention or reference any other font manager app anywhere.

Writing rules for all UI text: macOS HIG — Title Case for menu items, buttons and window titles,
sentence case for descriptions; short plain words; typographic apostrophes (’) in every string. No
ellipses anywhere, against the HIG: not on items that ask for more input (Export Fonts, Back Up), nor in progress text ("Finding fonts"; counts after
a comma: "Copying fonts, 3 of 10"). The one "…" left marks a cut-off preview in the coverage set editor; the menu items macOS adds (Services,
AutoFill, Start Dictation) keep theirs. SwiftUI's Settings… is called Preferences, without one (`PreferencesItem`):
SwiftUI puts that item's title back whenever the menu updates, and gives it to whatever holds ⌘, (a command group
of Cicero's own too, which leaves two items), so Cicero names its item again whenever any menu changes (SwiftUI can
put the Cicero menu in the menu bar whole, which only the menu bar hears of) and as one opens.

No hover states: nothing changes under the pointer (tooltips and the column-resize cursor aside). AppKit's
toolbar buttons and segmented pickers light up on hover in a grey of their own, so the toolbars use Cicero's
(ToolbarPicker, the .toolbar button and toggle styles, at AppKit's sizes): one grey for a toggle that's on
and a button being pressed. A picker's chosen segment is a grey lens of interactive glass, 3 pt inside the
capsule on every side, that slides to the next one chosen.

## Windows

1. **Main window** — sidebar | browser (or a font page pushed over it) | optional Info panel.
2. **Settings** — tabs General, Locations, Sidebar, Coverage (the character sets; a short name keeps the tabs evenly spaced). General's sections: Appearance, Menu Bar and Dock, Installation (where activated fonts' files go, added duplicates), Activation (asking before many, Open at login, Adobe documents' fonts), Library (what's listed, Adobe apps' test fonts included, guessed classifications), Maintenance, Updates.
3. **Character Toolbox** (⌥⌘T) — tabs Text and Languages.
4. **Compare** (⌥⌘C, or Window → Compare).
5. **Quick Look** (Space in the browser, ⌘Y) — a floating panel with the selected family.

Closing every window leaves Cicero running, so app folders and Adobe documents' fonts keep working; the Dock icon or Cicero's icon in the menu bar opens the main window again. The watchers for both start at launch (`didFinishLaunchingNotification`), not when the main window appears: AppKit opens no window at a launch that says it's a login item (keyAELaunchedAsLogInItem; checked with a simulated one).

## Sidebar

- Header "Library" with an **Edit**/**Done** button. Edit mode shows a checkbox on every row and every
  section header; unchecked items are dimmed, and disappear when you click Done. Sections and character set
  groups stay open or closed as outside it, and open and close the same way (one state for both). Switching
  isn't animated: hundreds of rows animating in and out ran into each other.
- Fixed rows: All Fonts (books.vertical), Active (checkmark.circle), Inactive (circle.dashed), Temporary (clock, only
  while a font is on until Cicero quits or while it's selected), Recents (tray.and.arrow.down; not a clock, which is
  Temporary's), System Fonts (apple.logo, only while system fonts are shown), Conflicts (exclamationmark.triangle, count
  badge). A saved order of these rows from before Temporary or Recents puts them last.
- Temporary (`SidebarItem.temporary`): the families with a style on until Cicero quits (Activate Temporarily, the
  Temporary tag), not app folders' fonts. It appears as soon as one is on, and goes when none is, unless it's
  selected: turning the last one off there leaves it, empty ("No Temporary Fonts", "Fonts you activate temporarily show
  up here until Cicero quits."), until another row is chosen. Its menu: Activate Permanently and Deactivate, for only the
  styles on until Cicero quits (`faces(in:)`), so the families' other styles stay as they are; no Export Fonts.
- Recents (`SidebarItem.recent`): the families with a style that arrived in the last 7 days
  (`AppModel.recentDays`), by `Family.lastAdded`: the latest Date Added of its styles (Finder's, else the file's creation
  date; see Library), leaving out styles that come with macOS or an app, whose files are as new as the last update of
  either; turning a font off and on again keeps its date (see Library). A family's Date Added column stays its earliest style's. On its own, it lists the latest first in every view
  (`Family.latestFirst`): families that arrived less than ten minutes after the one before came with it, as from one
  import, and keep the library's order among themselves; the list keeps that order, with no column's sort arrow, until a
  column's title is clicked, as for Show Similar Fonts, and again each time Recents is chosen. With other library
  rows selected too, the families of all of them in the library's order. No Export Fonts on its menu, like the other
  fixed rows. Empty: "No Recent Fonts", "Fonts that arrive on your Mac show up here for a week." A file opened
  where it is keeps the date it arrived in its folder, so an old one doesn't show; one Cicero installs a copy of does.
- Sections, each collapsible and hideable:
  - **Locations** (`SidebarSection.folders`, the watched folders; called Folders until sets took that name; + "Add a folder of fonts"). The folders Adobe apps load fonts from by themselves — /Library/Application Support/Adobe/Fonts, ~/Library/Application Support/Adobe/Fonts (all Adobe apps) and the Fonts folder next to any Adobe app, like /Applications/Adobe InDesign 2026/Fonts (that app only) — are one "Proofing" item (`WatchedFolder.adobeAppsID`; called Testing before, which read like trial fonts), shown while it has fonts (row menu: Reveal in Finder). Adobe Fonts (every CoreSync file, on for every app or only in Adobe apps) are one "Adobe Fonts" item (`adobeFontsID`), shown while it has fonts, whatever the switch (row menu: Manage in Creative Cloud; no Export Fonts); a family is in it when any copy is, like a location. Type designers export fonts there to test them; they're unrelated to Adobe Fonts from Creative Cloud (CoreSync), which are always listed and tagged "Adobe Fonts", never "Adobe". They aren't among the user's locations: Settings → General → Library → "Show fonts installed for proofing in Adobe apps" (on by default; saved as `showAdobeAppFolders`, formerly `showAdobeFonts`) switches them, and only them; adding one of them with + turns the switch on. Every row's menu here starts with Rename Location (a prompt with the current name; the name lives in `UserData.folderNames` by folder ID, the folder on disk keeps its own; empty or the folder's own name removes it; shown wherever a location's name is: sidebar and window title, Settings → Locations, smart folder rules, Conflicts, Use Copy From; Cicero's own items take one too; forgotten when the folder is removed). Row menu for the user's own locations: Reveal in Finder; "Fonts in This Location" picker —
    "Inactive" / "Active" / "Active in Adobe apps" / "Active in Specific App" (asks for its name); Remove Location from Library.
    Cicero's own "Added Fonts" (doc) appears here when it has fonts, the files added one at a time (see Opening and
    adding files; row menu: Reveal in Finder, which selects them). Never its Inactive folder (Inactive lists those
    fonts) nor its Font Library (see Activation), which takes the place of ~/Library/Fonts.
  - **Folders** (`SidebarSection.sets`; called Sets before, and their code still says sets; + menu, "New folder or smart folder": New Folder, New Smart Folder, New App Folder). Folders (folder), app folders (app.badge.checkmark; application sets in the code, and unrelated to app-folder fonts, which are in an app's own Fonts folder) and smart folders (gearshape). A folder's menu has Activate with Apps (Edit Apps once it has some), which makes it an app folder.
    Menus start with Activate Folder, Activate Temporarily and Deactivate Folder
    (Activate Smart Folder, Deactivate Smart Folder), for every family the row shows; then Rename Folder, Delete Folder
    (an app folder's too); Edit Smart Folder, Delete Smart Folder.
  - **Tags** (`SidebarSection.tags`; a family has any number, the license tags to begin with, on no family; called
    License in 0.5 to 0.5.2, when a family had one at a time; + new tag: the New Tag sheet, a name and a
    row of colour dots, None, the Finder's seven and sand, starting on the first colour no tag has; an empty name
    is the colour's; a name that's taken says so and can't be created). A new library starts with Licensed (green),
    Unlicensed (red), Open Source (blue) and Trial (orange); up to 0.9.1 also Licensed + Non-Commercial (sand),
    Partially Licensed (yellow) and Public Domain (purple), which a library from then loses once as it loads, each
    when in its colour, on no family and in no smart folder. One row per tag in the order they were made, a dot in its colour (a picture,
    not a tinted symbol, which the list darkened on the accent colour; or tag when it has none). Menu:
    Rename Tag (a name that's taken says so), Color (None, Red, Orange, Yellow, Green, Blue, Purple, Gray,
    Sand; each with its dot, as are tags in a family's Tag menu: `.titleAndIcon`, since menus built
    with the macOS 27 SDK hide images otherwise), Delete Tag (off every family, and out of smart folder rules).
  - **Foundries**. Menu: Rename Foundry
  - **Classifications** (+ new classification). Serif, Sans Serif, Monospaced, Script, Ornamental, Symbol — only the ones
    with families — then the user's own (always shown, in the order they were made), then Unclassified. A family's
    classification is the one its fonts suggest unless the user put it in another: the family menu's Classification
    submenu (Automatic (Sans Serif), every classification, New Classification; a classification is checked when the
    user put every family in it, so choosing the one Automatic suggests keeps the family there), the Info panel's Classification row
    (Change menu, the same items), or dropping families on a classification row. Menu: Rename Classification (built-in
    ones too; their own name back undoes it; a name that's taken says so; overrides, smart folder rules and the sidebar
    follow), Delete Classification for the user's own (its families go back to Automatic, its smart folder rules go).
  - **Coverage** (titled like the Settings tab; + new custom set). Collapsible groups — Latin S–XL, Adobe Latin, Google Fonts, Unicode Blocks, Your Coverage Sets — with every set shown unless hidden (Edit, Settings). The section starts collapsed, as Foundries does (Classifications starts open), and within it Unicode Blocks and Google Fonts. Menu for custom: Edit Coverage Set, Delete Coverage Set.
- The menus of folders, smart folders, tags, locations, foundries, classifications and character sets also have Export Fonts (that row's families, see Export and backup). Every row menu also has Hide from Sidebar (but All Fonts', Active's and Inactive's, which always show: `SidebarRow.alwaysShown`, their checkboxes in Edit and Settings → Sidebar on and disabled, a drag out of the list leaving them, an earlier version's hiding of them ignored) and Edit Sidebar, and so does a character set group's title, where Hide from Sidebar hides every set in the group (`hideGroup`), and with them the group.
- Order: rows drag to a new place within their own section (character sets within their group), never
  into another one; as in Finder's sidebar, the rows around the place they'd land slide apart to open a gap
  for them. Character set groups move by dragging a group's title onto another's, which is highlighted: the
  dragged group takes its place (a click on the title opens or closes the group, so the title can't also
  drag in the list). Sections don't move: a click on a title opens or closes it, and a drag does nothing (an
  order saved when sections could be dragged is kept; Reset Order puts them back). Items that are gone for now (System Fonts while
  system fonts are off, an empty Inactive folder) keep their place; new items go last.
- Rows dragged out of the list and let go of there, where nothing takes them, go as their menus would (`dragOutOfSidebar`),
  as Finder's sidebar removes them: locations leave the library (Remove Location from Library), folders, smart and
  app folders and tags are deleted (Delete Folder, Delete Tag), and Cicero's own locations, which can't be removed, and
  every other row are hidden; with a toast, "Recents hidden from the sidebar", "Trial deleted", "Downloads removed
  from the library" ("4 items", "4 tags", "4 locations" for more than three; joined with "and" when a drag does two),
  with Undo, which puts back the lists they changed as they were (fonts a removed location had on stay off). While they're outside, the pointer
  has Finder's × (`NSCursor.disappearingItem`, set at each move from the outline view's `draggedImage:movedTo:`)
  and they don't slide back. Escape, or letting go back in the list, keeps them; the picture never slides back to where the rows were (`animatesToStartingPositionsOnCancelOrFail` off), so rows let go where nothing changes, as in their own place, are there again at once rather than after half a second of the picture sliding back and fading. A dragged row is drawn by Cicero,
  its symbol and title in the label colour at the row's size (`SidebarDrag.picture`), at 88 % as Finder's rows
  are (measured on macOS 26); the list's own picture had a white symbol beside black text on macOS 26. Rows dropped in a new place land at
  once: the gap closes without animating (AppKit's closing slid the rows below up, cut off at their edges). Character set
  group titles don't hide this way.
- Several rows of one section (or character set group) can be selected with ⌘- and ⇧-click and dragged
  together: they land side by side in the gap, in their order. The browser then shows the fonts in any of them. Selecting in another section starts over there.
- The menu of one of several selected rows, which the list rings together, is for all of them (`AppModel.menuTargets`,
  `SidebarRowMenu`), as a family's menu is for the selected families; a row that isn't selected gets its own. It starts
  with how many ("3 Tags") and has what works on several: Activate Folders, Activate Temporarily and Deactivate Folders
  (Smart Folders when they're all smart ones), every font of them once; Reveal in Finder (not Adobe Fonts); Remove
  Locations from Library (the user's own locations among them); Delete Folders (smart ones too); Color, checked when
  every tag has it, and Delete Tags; Delete Classifications (the user's own among them); Delete Coverage Sets (the
  custom ones, one question for all: "Delete 3 coverage sets?"); Export Fonts (every family of them once, as "N
  Families"); Hide from Sidebar. What's one row's is left out: renaming, Edit Smart Folder, Activate with Apps,
  Edit Coverage Set, Fonts in This Location, Manage in Creative Cloud, and Temporary's Activate Permanently and Deactivate.
- Moving through the sidebar quickly (holding an arrow key, clicking from row to row) moves the selection at
  every step; the browser shows the last one once the selection rests for a moment.
- Dropping family names (drag from the browser or the Character Toolbox; dragging one of several selected families drags them
  all, as their menu acts on all of them) onto a folder, tag, foundry or classification adds them; the
  row they're over is drawn in the accent colour with white title and symbol (a status's dot keeps its colour).
  Drags are AppKit's (`FontDragSource`, started from a drag gesture): what's dragged is a small label at the pointer,
  "Aa" in the family's regular style and its name, with a red count when it's several, or a style row's name in that
  style. Drops land on AppKit views behind the rows and the Compare window (`FontDropTarget`), which leave clicks to
  the rows, so the label goes the moment it's dropped, as in the Finder. With SwiftUI's draggable the dragged item had
  the whole card's frame, and on macOS 26 the label slid to that frame's corner after a drop; SwiftUI's drop
  destination also held it up a third of a second longer.
- The list draws no selection (`selectionHighlightStyle = .none`): a selected row has its title and symbol in the accent
  colour on a light grey rounded fill, whether or not the list has focus (`SidebarHighlight`).
- Creating a folder, tag, classification or coverage set un-hides its section.
- Settings → Sidebar lists the same items, in the sidebar's order, as Finder-style checkboxes, with
  Reset Order and Show All.

## Browser

- Title = selected item's name (several: "Serif and Script"); subtitle "1.298 families · 716 active" (or "… · checking characters, 400 of 1.298" while coverage is computed and the list depends on it).
- Toolbar, left to right, each in a glass capsule of its own, 8 pt apart like the Info button and the search field
  (ToolbarCapsule: AppKit merges neighbouring items into one capsule, and ToolbarSpacer(.fixed) leaves 16 pt): view switcher
  [List list.bullet | Grid square.grid.2x2 | Specimens rectangle.grid.1x2] · [Preview Options textformat.size] · [Info info.circle] · native search field, with tokens (`SearchToken`), tinted as AppKit draws a tinted token, with the highlight colour as Light mode has it, 2.2 times as saturated, in both modes (the highlight colour itself came out too pale), rather than SwiftUI's grey (`SearchTokenTint`).
- **List** (rows under column headers in a lazy stack, like the grid: not a SwiftUI Table, which makes every
  row's cells whenever an accessibility client — a password manager's autofill, say — walks the window, and
  with a thousand families kept the app busy for minutes each time it came to the front): Status (switch) ·
  Name (+ tag dot, status tag) · Preview (sample in the font, 17 pt) · Styles · Classification · Foundry · Year
  (hidden; the earliest year among the family's faces: each face's earliest 1950-or-later year in its copyright notice, else
  its head table's created year from 1985 on; read when scanning and kept in the face cache) · Rating (hidden; the
  family's stars, ★ to ★★★★★, empty for none; sorts by stars) · Latin S–XL
  (largest of Latin S/M/L/XL the family fully has) · Adobe Latin (shown as "AL 3") · GF Latin, GF Cyrillic,
  GF Greek (hidden; largest of each script's Google sets, shown as "Plus"; GF Latin African branches off
  Core, so it isn't in the series) · any set no series covers: a Unicode block, GF Latin African, a custom
  set (hidden; ✓ when the family has all of it, "12 missing" when some) · Date Added (hidden) · Format
  (hidden). The headers are a bar under the toolbar (`safeAreaBar`, with the hard scroll edge effect), so
  the rows go under both together. Click a header to sort by it, again to reverse; right-click the headers to
  show or hide columns, the character set columns (series, then built-in single sets, then the user's own after a separator) under Coverage (Status,
  Name and Preview always show); drag the gap between two headers to resize the column on the side away from
  the preview, which makes up the difference, so the edge follows the pointer (shown columns and widths saved).
  When the room runs short (the Info panel open), the preview gives way first, then the other columns down to
  their minimums. The preview isn't clipped to its row: tall glyphs run over the row's edges rather than lose
  their descenders. Selection as in the other views.
- **Grid**: tiles — status tag + switch on top, big centered sample ("Aa Gg 123", or the sample
  text when set), name with its tag dot, and what the family's styles span, in Title Case: "9 Weights · 3
  Widths", "8 Weights · 16 Styles"; at the bottom right, the kinds of file it comes in ("OTF",
  "Variable", "OTF · Variable": extensions in capitals, variable fonts just "Variable"). No axis
  ranges: a variable font's styles are its named instances, placed by their axis values; a static
  font's by its names and classes. Weights count the words in style names (Bold, Bd, U Lt) first — many static files leave
  every class at 400 and variable fonts nudge instances off round values — then the axis value or
  OS/2 class. Widths: a variable instance's wdth value, with instances whose names write the same
  width words (Condensed, not XXX Condensed) counted once; a static font's OS/2 width class unless
  it's normal, then the name. A family with more styles than weight and width tell apart (italics,
  optical sizes, other axes, small caps cut as fonts of their own) adds "N Styles". One weight goes unsaid
  ("2 Styles", "2 Widths"), and a family with one style says "1 Style". The full caption is
  the tooltip. 10 pt beside a tile's contents, 14 pt above and below. Tiles fit the type
  (`FontGrid.Measure`, from the sample — the preview text, else "Aa Gg 123" — in the system font at the preview size, so
  every tile gets the same): the sample is as high as those letters reach above and below the baseline, plus a quarter
  of the size + 44 pt, and at least 0.36 times as high as the tile is wide with the sidebar shown and the Info panel
  shut (`sampleHeightPerWidth`), so wide tiles, two or three in a row, aren't flat, and hiding the sidebar or opening the
  panel doesn't make them higher or lower.
  Tiles are as wide as the library's families need, so all but the widest of them are drawn at the preview size, whatever
  their own width (a monospaced font is about 1.2 times as wide as the system font): `SampleWidths` measures each
  family's sample — in the style its tile shows, the text it draws (in the font's own script where it has to), with the
  axes and features it's drawn with — once, off the main thread, as a width per point of the size (from the leftmost of
  its first glyph's outline and its line's start to the rightmost of its last glyph's outline and its line's end; outlines
  scale with the size, so dragging Size measures nothing, and a font is drawn at its size, never a smaller one, in
  proportion to its true width). Of the families All Fonts lists, in the styles they show without a search, the width
  that all but the widest twentieth stay within (all of them in a library of fewer than twenty) sets the tiles' least
  width, for every list and search alike: measured for each sidebar selection, a list with a few more wide fonts than
  another (Active next to All Fonts, without the narrower fonts for Adobe apps) had wider tiles, often one fewer in a
  row and so half as wide again and higher, from one click to the next. Files a reading would wait for (on a server, or
  kept online only) count once read. Measured again when the library, Show system fonts, Show fonts from Creative Cloud,
  the preview text or the weight change; until then the tiles keep the width they had; the last width is kept for the
  next launch. The widest
  twentieth (Zapfino's swashes, dingbats, the most extended faces), wider than the tiles' room (`SampleFit`: the tile's
  least width less 28 pt), are drawn smaller, until they're that wide. That room goes up with the size, not with the
  tiles, so they grow and shrink with the size like the rest. (Shrunk to fit its tile, a font stopped growing while the
  rest went on, until the tiles got fewer, as tiles stay as wide as they are until a row has room for one fewer or one
  more.) With the sidebar hidden or the Info panel open, every sample is bigger or smaller by as much as the tiles are
  wider or narrower, one factor for all, so they keep their sizes to one another (held to the narrower tiles' room
  instead, most fonts were drawn the same width): at the size times that factor, rounded down to a whole point
  (`GridScale`), which Preview Options' Size shows while the grid does, with the size chosen in its tooltip; a size
  picked then sets the smallest whole size chosen that the grid draws at that size, and the sidebar shown with the panel
  shut shows the size chosen again. The sidebar's room follows it as it slides in and out (`SidebarRoom`: where the
  browser starts in the window, against where the sidebar rests, 8 pt in on macOS 26, the furthest in its frame has
  been, as it's further out only while sliding and keeps its frame while hidden), so the grid zooms along with the slide
  rather than rearranging, and so does the Info panel sliding in and out; dragging the sidebar wider or narrower
  rearranges it, as resizing the window does. The list
  and specimens keep the size chosen.
  Every font's sample sits on one baseline, where the system font's letters are centred ("H"
  centres the capital, "g" the x-height and descender), whatever the font's own ascent and descent; it's drawn unclipped
  and at its whole line's height, never shrunk to the sample's (proposed less, SwiftUI shrank it and drew it below the
  baseline it reported). A tile is at least the size + 186 pt wide, as wide as the sample in the system font × 1.1 +
  28 pt, and as wide as the listed families' samples need (above) + 28 pt; as many
  tiles fit in a row as can be that wide in the rows with the sidebar shown and the Info panel shut, from one to five, as
  wide as fills the row, however many families there are. Bigger type, fewer and bigger tiles. Hiding the sidebar makes
  them wider and the Info panel narrower, never more or fewer.
  The type shrinks further, to 0.4 at most, only where its letters fit but its line doesn't: a first or last letter
  with a lot of room beside it.
- **Specimens**: cards like the grid's tiles (light grey, tinted and outlined when selected, 12 pt apart, 16 pt from the edges) — name, tag dot, status tag, "Foundry · N styles", switch; the sample at preview size, on the left; up to 14 style names set in themselves (+N more), each line of them on one baseline (`FlowLayout` lines its children up by their first text's baseline, not their tops, which sit as high as each face's ascent puts them).
- Tag dot: an 8 pt circle in the tag's colour, with no ring (side by side, 2 pt apart, for a family tagged
  several ways before 0.5). Cards are opaque (the card's grey on the window's background), so the
  picture dragged to the sidebar looks like the card.
- Selection: click, ⌘-click, ⇧-click, ⌘A, arrow keys (↑/↓ in the list and specimens; in the grid ←/→ a tile and ↑/↓ a row; ⇧ extends), Esc clears (closing Quick Look first when it's open), and so does a click between families or below the last, typing a letter jumps, Return or double-click opens the font page, Space opens Quick Look; rows are draggable as family names. Right-click → family menu.
- Search (`SearchQuery`) matches where a word begins (at the start, or after a character that's neither a letter nor a digit) in a family's name (its own, or the one it shows in the Mac's language), foundry (as the user renamed it too) or note, or a style's name, PostScript name, designer or vendor ID, so "am" finds American Typewriter but not every family from a foundry with "am" inside its name; when nothing in the listed families matches that way, runs may be inside words of names (not foundries, designers or PostScript names), so "vetica" finds Helvetica. Or it matches what kind of family it is, by terms that begin with what's typed: variable, monospaced/mono, italics/italic, the classification it's shown in (a built-in one also by its usual words: sans serif/sans-serif/sans, script/handwriting/cursive, ornamental/decorative/display, symbol/dingbats), display or text (a name's size word, as similar fonts read it, or an opsz axis), condensed/compressed/narrow and extended/expanded/wide (a style off the regular's place on a wdth axis, else off OS/2 width class 5), slab serif/slab (OS/2 family class 5), optical size/opsz, its tags, its file extensions, and for a monospaced family what its family class says. The query's words split into runs that each match something, so "variable sans" finds variable sans serifs. A run that's exactly one of those words (a keyword) is looked for only in the family's and styles' names and the note, not the foundry, designers or PostScript names, so "mono" doesn't list Monotype's fonts. A query can also name a style (`SearchQuery.Style`), by words for a slope, width or weight spelled out: italic/italics/oblique; condensed, compressed, narrow, extended, expanded, wide and their semi/extra/ultra forms; hairline, thin, light, book, regular, medium, semibold, demibold, bold, heavy, black and their extra/ultra forms ("semi bold" counts as semibold); not abbreviations like "it" or "bd", nor roman, super or ultra, and not words that begin a word in the family's name, which name the family ("condensed" for Avenir Next Condensed). The grid, list, specimens and the font page's Automatic style then show that style of each family it finds (`Family.previewStyle(for:weight:)`): of its italics (uprights otherwise), those nearest the width named, on its side of normal; then the nearest weight, by the style's name before its OS/2 class, the one named or else the preview weight (400, the regular); a variable style with a weight axis before a static one, and of variable styles, with a weight axis or not, the ones where the regular is on the axes not named. A variable style of the weight named is drawn where it sits on its weight axis (not every font's is on the OS/2 scale), any other at the weight named. A family without such a style shows the nearest it has. Filters can also be tokens in the field (`SearchToken`, chosen from the suggestions; `AppModel.searchTokens`, applied at once, not after the pause): Italic; a weight (Thin, Extra Light, Light, Regular, Medium, Semibold, Bold, Extra Bold, Black); Condensed or Extended; Tabular Figures; Old-Style Figures. Only the last of each kind stays, so a second weight takes the first one's place. A family matches when it matches the text and every token: one of its styles is everything the style tokens say (italic; of the weight, by its name to the nearest hundred, so Book is a Regular and Heavy a Black, else its OS/2 class, or a variable style whose weight axis reaches it; narrower or wider than normal, as `Family.widthClass(of:)` has it), and one of its styles can set the figures (`FontFace.figures`). The previews show the style the tokens and the typed words name together (italic if either says so, the tokens' weight and width before the words'; a token's even where the family's name has the word), and turn on Number Spacing: Monospaced and Number Case: Lower Case for the figure tokens (`AppModel.searchFeatures`; on the font page with the Features tab's settings, which win for the same feature). Show Similar Fonts, Show in Library and adding fonts clear the tokens with the text (`clearSearch`).

## Similar fonts

- Show Similar Fonts (family menu, Fonts menu): the browser shows the family and the 12 nearest of the listed families (`SimilarFonts.longestList`), the closest first, in any view, like a search: no sidebar item selected, title "Similar to Inter", the search field cleared and then filtering them, the family selected and brought to the top. A bar over the list (a safe-area bar, under the toolbar): sparkle.magnifyingglass, "The families that look most like Inter, the closest first.", Done (plain text in the accent colour; back to the sidebar items selected before, the family selected there when it's listed, and to the font page that was open, if any). Choosing a sidebar item ends it too. The list keeps the order, with no column's sort arrow, until a column's title is clicked.
- Measured (`LetterMeasurements`): each family's regular style, a variable one at weight 400 and at its own optical size (the one its variation sets, else the axis's default: CoreText's automatic optical sizing is off, as it would size the font to the 1,000 units it's measured at and take an axis's default for none set, making every one its largest, display cut), from the outlines of H, I, O, a, c, d, e, g, l, n, o, p, x at 1,000 units to the em, against the H's height: x-height, ascender (l, d), descender (p, q), weight (the H's and n's stems), contrast (the o's top and bottom against its sides, the H's crossbar against its stems), stress (the o's thickness going round as a wave, its tilt from upright times how much it changes), width (the lowercase's average advance against the x-height), capital width, the o's width against its height, spacing (the room either side of n, o, H, O), slant (the font's angle, else the I's and l's lean), serifs (how far the feet of H and n reach past the stems and how thick they are, past a cupped foot's hollow; the I's and l's when neither can say), aperture (the share of directions out of c and e that meet no ink), squareness (how much of its box the o fills), the a's and g's stories (crossings going up through the middle), monospacing. Too few measures (fewer than 10 of 18) and the face isn't measured: most fonts of other scripts, symbol fonts, bitmap emoji.
- Embedded (`LetterEmbedding`): the same style, at the same optical size, its H O R A a e g n o s t y f k 2 5 drawn from their outlines (`LetterImages`), white on black, each centred in a 64-pixel square on a baseline 18 pixels up, at a size that makes the x-height 20 pixels (the capitals 40 at most), with each letter's advance at that size, in squares (what the squares, centred by the ink, don't show, as how a monospaced face's letters are all as wide), given to a Core ML model (Resources/LetterEmbedding.mlpackage, about 3 MB, compiled into the app by build-app.sh) that answers 128 numbers of length 1, close together for faces that look alike. The model learned from about 1,200 Google Fonts families (OFL, Apache and UFL only, the tenth of them it was judged on left out; scripts/embedding), each family's uprights at each width and optical size and its italics a design of their own, batched with its siblings named for another size, width or kind (DM Serif Display and Text, Roboto Mono and Roboto): designs as close as their Google tags of kind (Didone, geometric, formal script, stencil…) are alike, an upright and an italic less so, and two weights of a design closest, each design told from the others as well, so that slant and width count; Google's tags, category and the letter measurements, the widths most, told from them. Fewer than 8 of the 16 letters and the face isn't embedded.
- Compared (`SimilarFonts`): each measure in fixed steps of about a visible difference (not the library's spread, which for contrast is mostly the gap between sans serif and serif faces, and for slant next to nothing), capped at 4 steps, weighted (width 6, capital width and round width 3, as the embedding hardly tells widths; weight and serif length 2.5; contrast, monospacing 2; x-height, slant 1.5; stress, serif thickness, aperture, the a's story 1; squareness, the g's story 0.75; ascender, descender, spacing 0.5), a measure only one has counting 1.5 steps, one neither has none; the embeddings' distance in steps of 0.1, weighted 1.5. Families of different classifications (as the sidebar has them, guesses and the user's own included) are 1 further apart, added to the distance: a few places down a list, where the sixth nearest and the twelfth are often less than one apart, not out of it. Of families whose names say a size (`SimilarFonts.OpticalSize`: Text, Caption, Micro, Agate; Display, Headline, Poster, Deck, Banner, Titling, Fine), those of the family's own come first among them, in their order, then the others, its sibling for the other size among them, when its name says one too; families whose names don't say keep their places. Copies of one design, as their names say (`SimilarFonts.design(of:)`: the name without a leading Test and without Trial, Unlicensed, Test, Demo, Beta, Variable, VAR, VF, Pro, Std, Plus, ProN, StdN, SC, TC, HK, MO, a weight (Semi Bold as one), a version or a date (v0.2, 2.001, 260417) at its end, also before an Italic or Oblique there), are listed once, the nearest of them, and the family's own not at all. Done over the 12 nearest designs whatever the limit, so a font page's six are the start of Show Similar Fonts' 12, and a sibling among the 12 stays in it. Families hidden from lists are left out.
- Not Similar (a font page's Similar rows, the family menu in Show Similar Fonts' list): the user says families listed among another's similar fonts don't look like it (`AppModel.markNotSimilar`). They're kept in the user data (`UserData.notSimilar`: family → the families marked, the latest last; empty lists are dropped as it loads; kept when a family goes to the Trash, as its copies still count; in backups), and leave the family's list at once, with nothing in their places, so it's that much shorter (`SimilarFonts` takes the nearest 12 and leaves them out, so a font page's six are still the start of Show Similar Fonts' list); it leaves theirs, and every copy of either (`design(of:)`) is left out the same way. Marked ones leave the selection. Toast "Futura marked not similar to Inter" ("3 families marked…") with Undo, for 6 seconds (`AppModel.undoTime`), which takes back only those. While usage statistics are shared, each mark is also reported (`SimilarReports`, see Data and privacy) once Undo has passed, so a mark undone is never sent (without them it stays in the user data only); the report holds the list as it was before the mark.
- `MeasurementIndex` measures and embeds every family's regular style after coverage, on all cores at utility priority (about a second for a thousand families on an M-series Mac, and a third of one more for the embeddings, the model on the Neural Engine one family at a time), and keeps the results in Caches/letters.plist by file stamp; Rebuild Font List clears it. Raise its version when measuring or the model changes.

## Library and fonts

- Sources: everything CoreText reports active (`CTFontManagerCopyAvailableFontURLs`), macOS's own /System/Library/Fonts (CoreText's lists leave out some of its fonts, like Times, Courier, Iowan Old Style, Seravek and many Noto fonts, though apps can use them; its files count as active, from macOS, and its hidden "." families are left out as anywhere), ~/Library/Fonts and /Library/Fonts, watched folders, the files added one at a time (Added Fonts; skipped while missing or dataless), Cicero's Inactive folder (~/Library/Application Support/Cicero/Inactive). A file in the Fonts folders is active when CoreText lists it, or, for the few it leaves out (fonts with hidden names), when `CTFontManagerGetScopeForURL` says so; otherwise it's not activated (it's turned off in macOS, or macOS hasn't noticed it yet). Without a list from CoreText at all, files in the Fonts folders count as active. Files Cicero registered itself (in place, or for a while) that the list leaves out are asked about the same way: the list hides some fonts though they're on, like copies of the macOS fonts it hides. Files in watched folders that iCloud or another file provider has taken off the Mac (dataless) are skipped until they're downloaded: reading one would download it.
- Files: otf ttf ttc otc dfont (not web fonts, woff woff2, anywhere: not in locations, added files or CoreText's active list); each face read with CoreText (PostScript name, family, style, full name, OS/2 weight class (fallback from traits), OS/2 width class, italic, monospace, OS/2 family class, PANOSE (kind and serif style as a classification), letter shapes (below; only for faces with no family class and no monospace flag), manufacturer, version, designer (name ID 9), OS/2 vendor ID, wght axis range, visible variation axes (tag, name — the tag when the font gives none — and the named instance's value on each), embedding (the OS/2 fsType's usage bits; the least restrictive when several are set, as before OS/2 version 3), and the GSUB feature list's tags, kept as the `OpenTypeFeature`s smart folders ask for (ss01–ss20 as Stylistic Sets, cv01–cv99 as Character Variants, cswh as Swashes), and the figures it can set (`FontFileReader.figures(of:features:)`): tabular when all ten are as wide or by tnum, old-style when 0, 1 and 2 reach no higher than four fifths of 6 and 8 and three of 3, 4, 5, 7 and 9 reach below the baseline by more than 8 % of that, or by onum; in a font with a morx table, which has no GSUB features, also Number Spacing: Monospaced and Number Case: Lower Case as CoreText lists them; none without all ten figures). Unreadable files are kept for Conflicts. Parsed faces are cached by path + modification date + size (a face cache from before figures is read again whole, while a library saved with it still opens the window, `FaceCache.withoutFigures`); Date Added (Finder's, fallback creation date) is cached with them. macOS gives a file moved into another folder a new Date Added, so Cicero's own moves set the old one back (`ActivationEngine.move`, `setattrlist` with `ATTR_CMN_ADDEDTIME`, where the disk keeps one): into and out of the Inactive folder and an app's folder, and installed copies into the Font Library. A file from the Inactive folder, copied back into the Fonts folder or the Font Library, gives the copy its date; a copy installed of any other file is new.
- Families group faces by family name (hidden "."-prefixed families skipped). A family shows, and sorts, by its name in the Mac's language when its fonts have one (`LocalizedNames`): the name table's typographic family names (name ID 16, else ID 1) in every language but English are kept with each face in the caches, keyed by the full language ("ja-Jpan-JP"), Windows' and Unicode's records before the Mac's (in the script's encoding), so changing the Mac's language needs no reading again. The first of `Locale.preferredLanguages` the font has a name in wins, the region's own first, the same script only; English first means the fonts' own names. The family's id, which the user's data keys by, is always its own name; the Name rule and search match either, toasts use the one shown, and dragging a family carries its own. The same PostScript name in several files is one face: the active file wins, the others are "other copies"; Date Added is the earliest.
- Face state: active (from macOS / installed for all users / inside an app / Adobe Fonts (CoreSync) / your Fonts folder / used in place by Cicero / temporarily until Cicero quits / for an app folder / another app), inactive, or "active in <App> apps" for watched folders marked app-only and the Proofing folders. Also "Active in Adobe apps", as for Adobe's folders, for the Adobe Fonts Adobe apps turned on for themselves (as for a document), which Creative Cloud keeps under hidden names in ~/Library/Application Support/Adobe/CoreSync/plugins/livetype/.w (`Locations.adobeFontsInAdobeApps`, scanned always, hidden files included, and watched): app "Adobe", no item under Locations, and locked like every CoreSync file (`LibraryFace.isAdobeFonts`: no activate, temporary activation or deactivate; the switch sits halfway, disabled; the engine refuses them too). Such a copy ranks after every other, so a copy of the user's stays the face to switch, and it never makes a user's file spare (`SpareCopies`).
- Adobe Fonts pages: Creative Cloud lists the Adobe Fonts it keeps in ~/Library/Application Support/Adobe/CoreSync/plugins/livetype/.c/entitlements.xml (`Locations.adobeFontsList`), one `<font>` each with its `<id>` and, under `<properties>`, a `<familyURL>` on https://fonts.adobe.com/fonts/…; each font's file in .r (on for every app) or .w (Adobe apps only) is named after its id (".139.otf"). `AdobeFontsPages` reads it (only ever read; pages on fonts.adobe.com over HTTPS only; empty when it's missing or can't be read) and gives a family the page most of its copies from Adobe Fonts have. The app (`CreativeCloud`) reads it again when its modification date changes, looked at once a second at most.
- Family state: all active (system if all from macOS) / partly / inactive / app-only / system.
- Classification, the first that says something: monospace (any face), OS/2 family class of the lightest upright face that isn't a style of ornaments (class 12, or Ornaments or Dingbats in its style name, as Hoefler Text's), unless the family has nothing else (1,2,3,4,5,7 serif, slab serifs included; 8 sans; 9 ornamental; 10 script; 12 symbol; sub-classes don't change it), name hints (mono/code, stencil/inline/outline/fraktur/blackletter as ornamental, sans/grotesk/gothic, serif/slab/garamond/antiqua, script/brush/hand, symbol/dingbat/emoji), letter shapes, then PANOSE (kind 2 with serif style 2–10 serif, 11–13 sans, flared and rounded nothing; 3 script; 4 ornamental; 5 symbol; the proportion digit is ignored, as it often says monospaced wrongly). Letter shapes and PANOSE count when the upright faces (all faces, in a family of italics) that have one agree; letter shapes make a family monospaced only when every one of those faces is, and otherwise its monospaced faces don't count. Where both say something and differ, the letters are right, so they come first.
- Letter shapes (`LetterShapes`): monospaced when a drawn i, m and W (I, M and W without lowercase) are exactly as wide; letters not drawn yet, all as wide in unfinished fonts, and fonts in three widths (i and m alike, W wider) don't count. Else the capital I and lowercase l, flattened, measured with exact scanlines (non-zero winding). Each must be one stem: one run of ink at 30, 50 and 70 % of the glyph's height, widths within 1.3×, on a straight line leaning as the font's italic angle says, at most two contours. Serif when the ink 1–5 % from the bottom (and, for the I, from the top) reaches more than 0.3 stem widths past the stem on both sides of the I and at the foot of the l; sans when the I's ends reach less than 0.12 and the l's foot doesn't reach both ways (a tail to one side is fine). A font with only one of the two (capitals or lowercase only) goes by that one; an l alone is sans only with no tail either. Anything else (Verdana's serifed I with a plain l, scripts, italic l's tails) gives nothing: a wrong classification is worse than none.
- Guessing: while Settings → General → "Classify fonts automatically" is on (`classification.guessesFromNames`), the families still Unclassified get Apple Intelligence's guess from the name (macOS 26 only), else the model's from the letters (below). At the first launch (no user-data.json or library.json and no saved setting) an alert asks "Classify Your Fonts Automatically?" (Not Now, and Classify as the default button, side by side) as the window opens, and nothing is guessed until it's answered (`classification.asksAboutGuessing`, asked again at the next launch until then); a library from before keeps guessing as it did. Without guessing, what the fonts say still classifies them, as do the user's choices and classifications imported from FontExplorer X.
- Letter guesses (`AppModel.letterGuesses`): `LetterEmbedding`'s model also answers how likely its letters are serif, sans serif, script or ornamental (a small classifier on the embedding, fitted to Google Fonts' families: handwriting and script tags script; display families with a decorative theme ornamental; then Google's stroke, category or tags, slab serifs as serif; monospaced ones left to their advances). `MeasurementIndex` caches the likelihoods with the embedding; a family gets the classification when it's at least 0.7 likely (`letterGuessLikelihood`; held-out Google families: right 95 % of the time, saying something for 89 %), refreshed as measurements arrive. Not for a family whose letters say serif for some styles and sans for others. The Info panel then says "Guessed from the shapes of its letters".
- Name guesses (`ClassificationGuesser`, app; macOS 26, as macOS 15 has no model apps can ask): while guessing is on and `SystemLanguageModel.default` is available, the families still Unclassified are asked about one at a time in the background (not ones whose upright faces' letters say serif for some and sans for others, `Family.mixesSerifAndSans`: the model picks one of the two for them), in a new `LanguageModelSession` each, with greedy sampling and guided generation into serif / sansSerif / monospaced / script / ornamental / symbol / unknown. The prompt is the family name, foundry, designer and up to 12 style names. Answers, unknown among them, are kept in Caches/Cicero/classification-guesses.json (with the prompt's version), so each family is asked once; rate limits and missing model assets stop until the next scan, other failures until the next launch. A guess applies only while the family is Unclassified and has no classification the user chose, before the letters' guess (the model answers only when a name says); the Info panel then says "Guessed from the name by Apple Intelligence". Turning the setting off forgets the guesses. On-device only: never `PrivateCloudComputeLanguageModel`.
- Foundry: manufacturer name trimmed of Inc./LLC/GmbH/…, URLs and copyright lines dropped, casing unified; user can rename a foundry or set a family's foundry (drop onto foundry).
- At launch the window opens with the library the last scan built (saved in the caches after every scan that changes it; faces turned on until Cicero quit, or for an app folder in an earlier login session, show as off), and the launch's scan, started before the window is made, replaces it. What scans read goes into the face cache file by file, written every 2 s while reading goes on and as Cicero quits, so reading every file again after an update, cut short by quitting, goes on where it stopped at the next launch.
- Rescan: on launch, right after activation changes, on CoreText's registered-fonts-changed notification (posted to the app's own notification center, for any app's changes; debounced; while an operation runs they wait for the scan it starts when it finishes, or one right after it when it starts none), when font files come or go in the scanned folders (FSEvents), and when the app becomes active after ≥60 s. An unchanged scan must cost almost nothing (fingerprint; no UI churn). What previews and pages made from a file that changed, went away or came back is dropped (`Library.changedPaths`; a file the scan reads again starts afresh, `FontLoader.keep`): the grid draws a family once more as it leaves, from no file, which macOS answers with its LastResort font (boxes with question marks) for one that's on, and that stand-in mustn't stay once the file is back, moved out of a folder and in again or on a disk connected again.

## Export and backup

- **Export Fonts** (File, ⇧⌘E; "Export" in the family menu; "Export Fonts" in the sidebar menu of a folder, smart folder, location, foundry, classification or character set) copies the font files of the selected families — with none selected, of every family in the list; from a sidebar row, that row's families — into a folder or a ZIP archive, for sending them to someone or a printer. The save panel's name defaults to the row's name, the family's name for one family, or "N Families"; a Format picker in it chooses Folder or ZIP Archive. The folder holds one subfolder per family with its files; one family's files go straight into the folder. Each file is copied once (a collection shared by several faces, or families, once), only each face's own file, not its other copies. Files that come with macOS or an app, and Adobe Fonts, are left out and the toast says so: "Exported 12 families. Left out 3 font files that come with macOS or an app" (one or two by name: "Exported Inter and Roboto"). Files are copied with FileManager (APFS clones) off the main thread; a ZIP is staged in a temporary folder and made with `ditto -c -k --keepParent`. The export is built in a private folder on the destination's disk and takes its place only once complete, so a failed or cancelled one leaves nothing behind; an item the save panel confirmed replacing goes to the Trash then, never written over. An item that is, or holds, a font file in the library (an exported one, any other, or one Cicero's records name), ~/Library/Fonts, /Library/Fonts, Cicero's folder or its Inactive folder, or a watched folder is never replaced (by its path or where links lead): nothing moves and the toast says "“Fonts” holds fonts Cicero uses, so it wasn’t replaced. Choose another name or place." The result is revealed in Finder.
- **Back Up Library** (File; Settings → General → Backup) writes a `.cicerobackup` archive (a ZIP made with ditto), named "Cicero Backup 2026-10-13.cicerobackup" by default. A sheet first says what it holds — folders, smart folders, tags, coverage sets, locations and added fonts, foundry names, the sidebar, and the settings for activation, system fonts and fonts installed for Adobe apps — with a checkbox "Include font files" and their count and size ("3,812 files, 2.4 GB": every file in the library, other copies included, protected ones left out, sized off the main thread), then shows progress (a bar while copying, indeterminate while zipping) with Cancel, and reveals the file. Like an export, it's zipped in a private folder on the destination's disk and replaces an older file (through the Trash) only once complete, so Cancel or a failure leaves the older file and nothing else; it never replaces an item holding fonts Cicero uses. Inside: `manifest.json` (format 1, created date, app version, the home folder, `includesFonts`, and every font with its path — the home folder written as "~" — its place in the archive (`Fonts/<n>/<file>`, so names never clash), size, and how it was active: in ~/Library/Fonts, in place, an installed copy with its origin, or not active; `isOff` for a file that was off in ~/Library/Fonts, also one on only for now, which is off underneath; left out otherwise), `user-data.json` exactly as the store writes it, and the files.
- **Restore Library** (File; Settings → General) opens a `.cicerobackup`, unzips it to a temporary folder and asks "Restore the Backup from 13 October 2026?" with two checkboxes: "Folders, locations and settings" (what's inside: "4 folders, 2 smart folders, 7 tags, 3 locations, 12 added fonts and 1 character set", or "No folders or locations, just settings."; replaces the current setup, which is saved first to ~/Library/Application Support/Cicero/Backups/Before Restore <date>.json — the sheet says so) and "Font files" (only when the backup has them: "Puts each file back where it was, unless one is already there."). "~" means this account's home folder, so a backup moves between Macs and user names; the paths in the user data move with it (locations and added fonts). Nothing is ever written over: a file already at a path is left alone. A backup is a file anyone could have made, so nothing in it is trusted: only font files go back (the extensions the scanner reads); a file's place in the archive must stay inside the unzipped folder (no "..", no absolute path, no symbolic link), else it's left out; and a file goes back only to a plain absolute path (no "." or "..", after "~" is expanded) inside a font location: ~/Library/Fonts, /Library/Fonts, Cicero's Inactive folder, the watched folders and the Font Library in the backup's own user data (this Mac's library when only fonts are restored), Adobe's shared font folders and the Fonts folder next to an Adobe app. A file that was off in ~/Library/Fonts goes into Cicero's Inactive folder first (`FontRestoreResult.turningOff`), and the restore's queued operation moves it back in off (`moveIntoFontsFolderOff`) before the records are merged. Missing folders are made; a file meant for anywhere else, or that can't go back (no permission, or a folder next to an app that isn't installed, like /Applications/Adobe InDesign 2025/Fonts) goes into ~/Fonts Restored from Cicero/ keeping its path under it (without "." or ".." parts), and that folder is added to the watched folders (Locations). Records describe this Mac and follow the same rule (installed copies only in ~/Library/Fonts or the Font Library, app-folder origins only for files in the Inactive folder): the backup's installed copies count when both files exist and the copy is the backup's (this restore put it back, or it has the origin's contents; a different file this Mac already had there is no copy), its temporary activations are dropped, its app-folder origins count when this restore put the file back (activating would otherwise move a file this Mac already had into an app's folder), its in-place registrations are activated again (in place, through the activation engine) once a scan has found the faces, and the current records stay where their files exist. Then a rescan and a toast: "Restored 4 folders and 3,790 font files; 22 were already there." The file work runs off the main thread with progress and Cancel in the sheet; the records change is one queued operation, like an activation.

FontExplorer X's rule fields by number (`baseCriteria`, 7.3): Name 0, PostScript Name 1, Path 3, Family Name 4, Style 5, Copyright 6, Version 7, Trademark 8, Manufacturer 9, Comment 10, Designer 11, Description 12, Is Activated 100, Is in Conflict 101, Is in System Folder 102, Is System Font 105, Format 200, Vendor 300, Rating 400, Contained In 500, Not Contained In 501, Label 600, Number of Activations 700, Last Activated 701, Number of Last Activated Fonts 702, Import Date 800, Number of Last Imported Fonts 801, Embedding Rights 900, Language 1100, OpenType Features 1200, SkyFonts 1300, Monotype 1301, Adobe Fonts 1302, Classification 1500, Last Deactivated 1600; text comparisons (`subCriteria`) is 0, is not 1, ends with 2, doesn't end with 3, begins with 4, doesn't begin with 5, contains 6, doesn't contain 7; dates in the last 7 days 1007, 30 days 1030. A family's rating is its best style's, unless it has one; its note the comments on its files and styles, each once, one per line, unless it has one; its activations the most any of its files had and the latest date, Cicero's own if higher. The fonts that were active (activate = 1, not the system's or cloud fonts) are activated in place. Only ever adds, so importing again changes nothing.

## Applications folder

- Open at login points at the copy that's running, and Sparkle replaces that copy, so both need Cicero in /Applications or ~/Applications (or a folder inside them), not on a disk image, in Downloads or at an App Translocation path. At launch, a copy elsewhere asks "Move Cicero to the Applications folder?" ("App folders, opening at login and updates work only when Cicero is in the Applications folder."): Move to Applications Folder / Do Not Move, with a "Don’t ask again" checkbox. A binary run from .build (`swift run`) never asks.
- Turning on Open at login (Settings → General, or the apps sheet's Open at Login) outside an Applications folder shows the same alert without the checkbox instead of adding a login item; the moved copy then turns Open at login on.
- Moving copies Cicero.app into /Applications, or ~/Applications when the user can't write there; a Cicero.app already there goes to the Trash first (a Cicero running from it is asked to quit). The copy loses the quarantine attribute. The original goes to the Trash when it's on a writable volume, found through `SecTranslocateCreateOriginalPathForURL` when the app was translocated; a disk image it ran from is detached once Cicero has quit. A small shell script waits for Cicero to quit and opens the moved copy. A failure says "Couldn’t move Cicero to the Applications folder." with the reason.

## macOS 15

Cicero runs on macOS 15 and later (`.macOS(.v15)`, `LSMinimumSystemVersion` 15.0). What it uses of macOS 26 has a stand-in there (`Components/Compatibility.swift`), so on macOS 15 Cicero looks as that macOS's own apps do; macOS 26 is unchanged.
- Glass: the toast, the scanning capsule and Quick Look's bar are on the bar material with a hairline edge and a shadow (`glass(in:)`). The toolbar has the system's own controls, not Cicero's capsules: a segmented picker for the view and the Compare and Toolbox pickers (`ToolbarPicker`), the system's toolbar buttons (`toolbarButtonStyle()`) and toggles (`ToolbarToggleStyle`).
- Bars over a scroll view (the list's column headers, Show Similar Fonts' bar): an inset on the bar material that what scrolls goes under (`topBar`), without a scroll edge effect; the Toolbox's fading bars an inset too.
- Exact line heights (Quick Look's samples over several lines): the font's own line spacing plus what the setting adds; lines set tighter than the font's own spacing keep it (`lineHeight(_:natural:)`). The font page's sample (`SampleEditor`) is exact on both.
- Drag and drop (`drops(of:)`): `dropDestination(for:action:isTargeted:)`, which can't tell drags from Cicero's own windows (family drags are names, not files, so they don't outline the window anyway). Character set groups drag with `onDrag` (with `draggable` the title never started a drag there) and drop through a `DropDelegate` that proposes a move, forbidden onto the dragged group's own title.
- Sidebar sections are `collapsible(false)`, or the list adds a chevron of its own after a header's + (`notCollapsible()`).
- No Apple Intelligence model for apps: classifications are recognized from the letters only, and the first-launch alert and Settings → General say so (`ClassificationGuesser.readsNames`).

## Data and privacy

- Everything local: ~/Library/Application Support/Cicero (user data, Inactive folder), ~/Library/Caches/Cicero (face, library and coverage caches, classification guesses). Nothing about the user or their fonts is uploaded, but for not-similar reports (below); Apple Intelligence's guesses are made by the model on the Mac.
- Not-similar reports (`SimilarReports`, `SimilarReport`): when the user marks families not similar (see Similar fonts) and Undo has passed, while Settings → General → "Share usage statistics" is on (`usageStatistics.isOn`, as for the launch signal; there's no switch of its own), Cicero POSTs one JSON report to `https://cicero.maximilianinzinger.com/api/similar-reports` over an ephemeral URLSession: `format` 1; `app`, `build`, `macOS` ("26.1.0"); `model` (`MeasurementIndex.version`); `mac`, the SHA-256 of a random UUID kept in the defaults (`similarReports.id`); `test`, true for a build signed without a team; `shownIn` (`page` or `browser`); `family`, the family the list is for; `notSimilar`, the names marked; `list`, the list as the user saw it before the mark, the 12 nearest (`SimilarFonts.longestList`) whatever the page showed. Each family: `name` (its own, `Family.id`), `style` (the measured regular's PostScript name), `foundry` (as the user named it), `classification` (as the sidebar has it; none for Unclassified), `measurements` (`LetterMeasurements` by measure name, those it has), `embedding` (the 128 numbers), `distance` (from the family; none for it). No font files, nor pictures of letters. A failed send isn't retried. At most 20 reports a day from one Mac (`SimilarReports.dailyLimit`, counted by the Mac's own day in `similarReports.day` and `.count` as each is sent; a report of several families counts once), so no one Mac uses up the 2,000 the store may take a month on Vercel's Hobby plan (one advanced operation each; over it, the store is out of use for 30 days); marks past it stay on the Mac. Turning usage statistics off removes this ID and the count too, and a mark then stays on the Mac. Nothing is sent from a binary run from .build. The website's function (private repo) checks a report's shape and keeps it, with the time it arrived and without the IP address, as one file in a private Vercel Blob store in Frankfurt; a script there downloads them for the training kit.
- Usage statistics (`UsageStatistics`): when the app has finished launching, while Settings → General → "Share usage statistics" is on (it is from the start, without asking; `usageStatistics.isOn`), Cicero POSTs one TelemetryDeck signal to `https://nom.telemetrydeck.com/v2/` over an ephemeral URLSession: type `TelemetryDeck.Session.started`, a new session UUID, `clientUser` the SHA-256 of a random UUID kept in the defaults (`usageStatistics.id`), and the payload `TelemetryDeck.AppInfo.version` and `.buildNumber`, `TelemetryDeck.Device.platform` ("macOS"), `.systemVersion` ("macOS 26.1.0") and `.systemMajorVersion` ("macOS 26"). `isTestMode` is true for a build signed without a team, like build-app.sh's ad-hoc one. Until TelemetryDeck has answered with a 2xx while `usageStatistics.countedAsNew` was unset, the same request also carries a `TelemetryDeck.Acquisition.newInstallDetected` signal (the same user and session, the same payload plus `TelemetryDeck.Acquisition.firstSessionDate`, the local day like "2026-10-14"), which TelemetryDeck's Acquisition charts count as a new user; then the flag is set, and kept when the setting is turned off, so a Mac counts as new once. A failed send isn't retried, except that signal at the next launch. Turning the setting off removes the ID, so turning it on again makes a new one. Nothing is sent from a binary run from .build, or while `UsageStatistics.appID` is empty.
- Updates (Sparkle 2): each time Cicero opens and once a day while it stays open, while Settings → General → "Check for updates automatically" is on (it is from the start, without asking), Cicero downloads the appcast from the latest GitHub release (`SUFeedURL`); Check for Updates does it at once. Sparkle's system profile stays off, so the request carries nothing but its user agent, "Cicero/1.0 Sparkle/2.10.0". An update the user accepts is downloaded from GitHub and installed only if its EdDSA signature matches `SUPublicEDKey`. The appcast holds the latest version only, with its CHANGELOG.md section as Markdown release notes.
- The rewrite reads the existing user data file (library.json, read by `UserDataStore`) once and keeps working from its own file; the old file is never modified.
